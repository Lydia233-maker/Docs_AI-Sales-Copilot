## 1. 这个版本做了哪些功能

登录后可以走完：看客户 → 导入客户和订单 → 改语言或公司地址 → 沉睡召回 → 生成 → 通过 → 模拟发送 → 复制。

- 登录、退出。会话放在 Cookie 里。未登录访问业务接口返回 401。`/health`、登录和 `/u/` 不要求登录。
- 客户列表 40 人，可按英语或西班牙语筛选。
- 客户档案：国家、语言、订单数、消费金额、消费层级、主要品类、距今天数、是否同意营销、备注、偏好标签。金额按美元显示，库存的是「分」。
- 档案页可以在英语和西班牙语之间切换。保存后刷新仍在。再次导入客户 CSV 时，销售改过的语言保持不变；没改过的人仍按国家或标签判断。
- 左侧「店铺」可以修改公司地址。复制和模拟发送时，信的底部用当时保存的地址。改地址后不用重新生成。
- 「导入」可以上传 `fixtures/demo-pet` 的客户 CSV 和订单 CSV。预览不写账本。确认后按邮箱写入，并重算语言、国家、品类、最近商品、购买次数、距上次购买天数、消费层级和邮件营销同意。Note 里的邮箱和电话写成 `[已隐藏]`。
- 挑选客户目前有两个选项：沉睡召回（距上次购买至少 60 天），或全部客户。生成前显示总人数、可触达人数、排除人数，以及逐个定制和小群方式的人数。
- 用中文填写推广意图和折扣码，然后为每位可触达客户生成一封邮件。未同意营销的人留在名单里，不生成文案，也不发送。
- 每封邮件有外语标题、外语正文、中文对照和定制要点。发给生成逻辑的简报不能带姓名、邮箱或电话；带了就整批回滚，返回 400。
- 可以改正文、单份通过、一键通过。缺少退订链接、公司地址，或出现白名单以外的占位符时，不能通过。
- 模拟发送只处理已通过且同意营销的草稿。复制时在页面下方看到填好姓名、商品、折扣码、退订链接和公司地址的正文。上面的编辑框仍是带 `{{ }}` 的底稿。
- 账本里已经有弃单、弃单商品、事实、生成任务这四张表，以及改语言、改地址、确认事实的校验。页面还没有用上弃单和事实。

## 2. 已知限制和还没做完的部分

**导入和挑选**

- 弃单还不能上传。四个新场景（复购提醒、首单转二单、弃购挽回，以及按这四个场景挑选）还没接到页面上。挑选页仍是沉睡召回和全部客户。
- 不能按品类、消费层级缩小名单，也不能去掉或加回个别客户。生成前不显示调用次数和费用。
- 「小群方式」只是人数。生成时每个人仍然各写一封。
- 确认导入后的「西班牙语人数」是写入之后店里的人数。销售把一位英语客户改成西班牙语再导入，这个数字会从 16 变成 17。

**画像和聊天**

- 档案页仍有「添加备注」和「添加标签」。这两项按需求要在事实确认做完时去掉。
- 事实表是空的。商品标题里重复出现的说法不会变成待确认偏好。Gorgias 聊天还不能导入。
- `pnpm seed` 把 `fixtures/demo-pet/notes.json` 原样写入备注，邮箱和电话先不遮盖。用导入页确认同一份客户 CSV 之后，这两处才会变成 `[已隐藏]`。

**写信、审核、发送**

- 文案始终来自本地模板 `apps/api/src/templates.ts`。没有调用 DeepSeek。`/health` 只会显示进程里有没有钥匙，不会拿它去写信。
- 中文推广意图会原样出现在外语正文里。有折扣码时，折扣句固定写成 20% off。
- 生成是同步写完再返回。`generation_jobs` 表没有被生成接口写入。页面上看不到「正在写」或「中途停下」，也没有「继续写剩下的」。
- 不能只重写一封。审核接口仍接受驳回；页面上没有驳回按钮。
- 发送永远是模拟。退订链接会写进邮件，打开 `http://localhost:3000/u/<token>` 没有成功页，也不会把这个人记成已退订。
- 没有 WhatsApp，没有费用配置，没有三千人导入。

## 3. 怎么运行

在仓库根目录：

```bash
pnpm install
pnpm seed
pnpm dev
```

- 前端：http://localhost:5173
- 后端：http://localhost:3000
- 邮箱 `demo@example.com`，密码 `demo1234`

`pnpm seed` 会清空账本里的客户、订单、备注、推广、事实、弃单和生成任务，再灌入 40 人，并打印 `seeded 40 customers`。人数对不上时，先停掉服务，再执行一次。销售改过的语言和公司地址也会回到演示初始值。

`fixtures/demo-pet/` 里的 CSV 已经提交。一般不用再跑 `node fixtures/demo-pet/generate.mjs`。

如果 `pnpm seed` 报错说 better-sqlite3 找不到 `.node` 文件，在仓库根目录执行 `pnpm rebuild better-sqlite3`，然后再 `pnpm seed`、`pnpm dev`。

其他命令：

| 命令 | 作用 |
| --- | --- |
| `pnpm test` | 跑共享包和接口测试。网页包的 test 脚本直接退出 0 |
| `pnpm build` | 各包做 TypeScript 检查；网页还会做一次生产构建 |
| `pnpm --filter api exec tsx src/smoke.ts` | 对当前账本走一遍登录、沉睡人数、生成和模拟发送 |

程序不读取 `.env`。要固定「今天」，在启动后端的那个进程里设置，例如 `APP_NOW=2026-11-01 pnpm --filter api dev`。只写在 `.env` 里不会生效。

页面上可以这样核对任务 1 到 3：

1. 登录后侧栏是 Paws Demo。客户列表 40 人，语言选西班牙语是 16 人。
2. 打开「导入」，上传 `fixtures/demo-pet/customers.csv` 和 `orders.csv`。预览时人数不变。确认后仍是 40 人、西班牙语 16 人。Anna Cole 能看到订单金额，备注里仍有布偶猫或无尘猫砂。
3. 打开 Anna Cole，语言改成西班牙语，刷新后仍在。再导入同一份 CSV，她仍是西班牙语。这时店里西班牙语是 17 人。另一位没改过的美国客户，例如 Blake Young，仍是英语。
4. 打开「店铺」，地址改成 `456 Market St`，刷新后还在。
5. 「挑选客户」保持沉睡召回，点「开始生成」。打开 Anna，点「通过」，再点「复制」。按钮下面的灰色正文有 `456 Market St`，也有填好的名字。上面的编辑框仍保留 `{{company_address}}`。
6. 地址改回 `123 Demo St, Austin, TX 78701`，再点一次「复制」。灰色正文底部用回演示地址。

根目录 `README.md` 的端到端清单仍能从登录走到复制。那份清单还没写「导入」和「店铺」，第 4 步的添加标签在这一版页面上还在。

技术文档第 139 行之后的踩坑清单有四条已经被任务 1 到 3 做掉，接着改时不要再按旧句子实现：

### 临时方案，以后要换掉

1. **信纸。** `generateTemplate` 是现在唯一的写信方式。任务 8 要改成：有 DeepSeek 钥匙时按人和按组调用；没有钥匙、钥匙无效、超时或返回无法解析时，仍用这张信纸。回退时不能再把中文意图原句贴进外语。有折扣码仍写 20% off。不要接 OpenAI。钥匙只放在启动后端的进程环境里，不要写进代码、文档或日志。
2. **分组和费用。** `generationMode` 已经能标出逐个定制和小群，生成循环没有按组共用正文。费用要等分组接上再显示，次数等于单独写人数加组数。没配单价时页面写「费用还没配置」。
3. **生成任务表。** `generation_jobs` 只建了表，生成接口不写它。任务 9 再写入进度。在那之前，后端启动不会把「正在写」改成「中途停下」。
4. **事实和手写入口。** 备注仍在 `customer_notes`。`facts` 表还没有业务写入。任务 6 再从商品标题产生待确认偏好，并去掉「添加备注」「添加标签」。演示备注要留下，并视为已确认。
5. **弃单。** `abandoned_checkouts` 是空表。`apps/api/src/imports/index.ts` 里的 `abandoned` 只是类型名，没有读取器。
6. **驳回。** `ReviewDraftBody` 仍接受 `reject`。任务 10 再从接口和页面去掉。在那之前不要在页面上加驳回按钮。
7. **退订。** 链接指向 `http://localhost:3000/u/<token>`。这一版不做出成功页，也不要把打开链接写成已退订。登录校验已经放行 `/u/`。
8. **`/health` 里的另外两把钥匙。** 返回里还有 OpenAI 和豆包是否配置。产品决定是 DeepSeek，失败再用信纸。接模型时不要把这两项接成自动备用。

### 改代码时容易踩的地方

- **旧账本不会自己长出新列。** `CREATE TABLE IF NOT EXISTS` 不会给已经存在的 `customers` 补上 `language_overridden`。四张新表若建表语句里没有 `CHECK`，启动时会删掉重建。这四张表里先不要放要保留的数据。改完表结构后，在 `apps/api` 目录执行 `pnpm seed`。
- **数据库路径跟着进程的当前目录。** 默认文件是 `apps/api/data/app.db`，因为 `pnpm --filter api` 的工作目录是 `apps/api`。从仓库根目录直接启动后端，会另开一本空库。这个文件已被 git 忽略。
- **同一时间只跑一个后端。** SQLite 开着外键和 WAL。生成进行时再开一个进程，会锁库、写乱。
- **`pnpm seed` 会删掉整本账本再重建演示店。** 手里正在看的导入、改过的语言、公司地址和推广都会没。
- **订单 CSV 一行是一件商品。** 按订单 `Name` 合并。客户和订单用小写邮箱关联。订单金额先读 `Total`；没有总金额时，把各行 `Lineitem price` 相加，不乘数量。导入和种子用的是同一条规则，只改一边，Anna 的金额会对不上。金额用整数「分」，显示时再除以 100。
- **场景名单有两套，接任务 4 之前不要互换。** 挑选和创建推广用 `SCENARIOS`（`winback_dormant`、`all`）。四个新场景在 `AUDIENCE_SCENARIOS`。现在把创建接口改成四个新场景，现有页面会无法生成。
- **查询要带 `store_id`。** 现在只有一家演示店。漏掉以后会串数据。能否生成和发送走现有的 `isEmailEligible`，不要在新查询里另写一套同意条件。
- **接口用驼峰，账本列用蛇形。** `GET /api/v1/store` 已返回 `companyAddress`。`GET /api/v1/auth/me` 仍返回 `company_address`，网页只用了其中的店名。新增字段时同时改 `apps/api/src/app.ts` 和 `apps/web/src/api.ts`。
- **新增的请求体用 `.strict()`。** 多一个字段会 400。公司地址去掉空白后长度要在 1 到 300，数据库触发器也会拒绝更长或空白的地址。
- **没有正文的 POST 不要加 `Content-Type: application/json`。** `api.ts` 只在有正文时加这个头。生成、一键通过、模拟发送都是空正文。
- **占位符在复制和发送时才填。** 白名单在 `packages/shared`。公司地址从店铺表现读，所以旧草稿会用上新地址。新增占位符时要同时改白名单、`renderCopy` 和通过前的检查。
- **遮盖联系方式的电话规则也会碰上像日期的数字。** 备注先遮盖再送进简报。备注里若有一长串数字，可能被写成 `[已隐藏]`。调整规则时，种子备注和导入备注要一起看。
- **流程测试不要放进同一个 `tsx` 进程。** `store.flow.test.ts`、`import.flow.test.ts`、`outreach.flow.test.ts` 各自在导入数据库模块之前设置 `DATABASE_PATH`。`apps/api/package.json` 里它们是分开的 `tsx --test`。并进前一条命令会共用一本库。
- **网页开发服务只监听本机的 IPv6。** 用 `http://localhost:5173` 打开。`127.0.0.1:5173` 连不上。接口 `http://127.0.0.1:3000` 可以。
