演示店名 **Paws Demo**，账号 `demo@example.com` / `demo1234`。演示数据是宠物用品。程序里的「今天」默认是 `2026-11-01`。公司地址默认 `123 Demo St, Austin, TX 78701`。

`pnpm seed` 之后的人数：客户 40，西班牙语 16，沉睡 32，其中可触达 27（英语 14、西班牙语 13），排除 5。复购提醒 6 人、全部可触达。首单转二单 5 人、全部可触达。弃购挽回 4 人，可触达 3。明细在 `fixtures/demo-pet/README.md`。

## 1. 这个版本做了哪些功能

登录后可以走完：看客户 → 导入 → 改语言或公司地址 → 按四个场景挑选 → 看到费用 → 生成 → 审核 → 模拟发送 → 复制。

- 登录、退出。会话放在 Cookie 里。未登录访问业务接口返回 401。
- 客户列表 40 人，可按英语或西班牙语筛选。档案显示国家、语言、订单、消费金额和层级、主要品类、距今天数、是否同意营销、原来的备注，以及事实。
- 档案页可以在英语和西班牙语之间切换。销售改过的语言会记住，再次导入客户 CSV 时不被国家重猜盖掉。
- 左侧「店铺」可以修改公司地址。复制和模拟发送时，信的底部用当时保存的地址。
- 「导入」可以预览再确认三份文件：客户和订单、弃单、Gorgias「Export with message content」。预览不写账本。对不上的弃单或聊天单独计数，不挂到别人身上。空的聊天正文跳过。
- 挑选页有四个场景：沉睡召回（不少于 60 天）、复购提醒（猫砂 21 天、猫粮和狗粮 30 天、零食 14 天，上下 7 天）、首单转二单（正好 1 笔且距今 7 到 30 天）、弃购挽回（弃单在 1 到 7 天，且之后没有已付款订单）。可以再按语言、品类、消费层级缩小，也可以去掉或加回个别人。创建推广时按当时勾选的人冻结。
- 未同意营销的人留在名单里，标成「不生成」，没有草稿，也不会发送。没上传弃单时，弃购挽回写「还没有弃单数据」，不显示 0 人。
- 生成前显示单独写人数、共用组数、调用次数和费用。买过至少两次，或已有确认过的事实，算单独写。其余人按语言、国家、场景、消费层级、主要品类分组。调用次数等于单独写人数加组数。没设置 `UNIT_PRICE_CENTS` 时写「费用还没配置」。
- 同一客户的已付款商品标题里，同一种说法出现至少两次，会生成一条待确认偏好。Gorgias 对得上的原话也是待确认。档案页可以确认或忽略。只有已确认的事实会写进信。演示数据里原有备注仍显示，并视为已确认。没有钥匙时，聊天原话不编造类别，状态是「还没分类」。
- 没有 DeepSeek 钥匙时用本地信纸。外语正文能看出商品、天数和品类。有折扣码时写 20% off 或 20% de descuento，不把中文意图原句贴进外语。同一组的人共用正文，复制后的姓名和上次商品是各人自己的。
- 有钥匙时，每封单独写的信和每一组各调用一次 DeepSeek。发给模型的简报不能带姓名、邮箱或电话。某一封失败时，这一封改用信纸，其余照常保存。
- 按下生成后接口马上返回。页面显示正在写、已写完或中途停下，并写出计划封数、已写完封数、还没写的从谁开始、失败封数。后端重新启动时，仍是「正在写」的任务改成「中途停下」。「继续写剩下的」只补没写完和失败的，不改写已经写好的信。
- 审核页标出用了哪些已确认事实。可以改正文，也可以只重新生成这一封。没有驳回。删掉 `{{unsubscribe_url}}` 或 `{{company_address}}` 时不能通过。
- 模拟发送只处理已通过且同意营销的草稿。复制和发送后的正文没有留下 `{{`。退订链接会写进邮件，打开没有成功页。

## 2. 已知限制和还没做完的部分

**写信**

- 本地信纸不会翻译任意中文意图。有折扣码时，外语优惠句固定是 20% off。中文对照里写成「优惠说明」，不是把「黑五老客专享 8 折」原句贴进去。真正按意图改优惠，要配 DeepSeek 钥匙。
- 没有 OpenAI 或其他模型备用。钥匙无效、超过约 20 秒或返回无法解析时，这一封改用信纸。
- `/health` 仍会报告进程里有没有 `OPENAI_API_KEY` 和 `DOUBAO_API_KEY`。这两项不参与写信，不要接成自动备用。
- 同一组的底稿不含具体天数和具体商品标题，复制时才填 `{{first_name}}` 和 `{{last_product}}`。单独写的信会把商品标题写进底稿。

**发送和退订**

- 发送永远是模拟，没有真实邮箱。
- 退订链接指向 `http://localhost:3000/u/<token>`。打开是 404，没有成功页，也不会把这个人记成已退订。

**画像和聊天**

- 聊天只接 Gorgias 这一种 CSV。这一版只读 `Customer email` 和 `Message text`。别的客服系统没有入口。
- 没有钥匙时，导入的聊天是「还没分类」且待确认。确认后原话可以进信，但系统没有替你判断它是偏好还是需要小心的事。
- 商品标题的抽词按空格切开、至少 4 个字母、至少两行出现。像 `Litter` 这种普通词也会变成待确认偏好，要人来忽略。
- 忽略会删掉这一行。没有「已忽略」的墓碑。再次导入或再次 `pnpm seed` 时，同样的标题仍会重新出现为待确认。
- 页面上已经去掉「添加备注」和「添加标签」。对应的两个接口还在，直接调用仍能写入。新备注不会自动变成事实，除非再走一遍客户导入或种子里的事实同步。
- `pnpm seed` 把 `notes.json` 原样写入备注。用导入页确认同一份客户 CSV 之后，备注里的邮箱和电话才会变成 `[已隐藏]`。写信时仍会再遮盖一次。

**挑选和费用**

- 挑选页上的调用次数和费用，是按当前场景和筛选算的，还没扣掉你刚取消勾选的人。创建推广时用的是勾选之后的名单。
- 确认导入后提示的「西班牙语人数」是写入之后整店的人数。把一位英语客户改成西班牙语再导入，这个数字会从 16 变成 17。
- 不编造零售、批发或客户类型。页面上没有这些字段。

**规模**

- 三千人测试走的是本地信纸，不调用真实模型。它证明导入和模板生成能写完，不证明 DeepSeek 能在同样人数下按时写完。
- 挑选在内存里过滤客户。三千人可以，再大一截要另做分页。

## 3. 怎么运行

在仓库根目录：

```bash
pnpm install
pnpm seed
pnpm dev
```

- 前端：http://localhost:5173
- 后端：http://localhost:3000
- 邮箱 `demo@example.com`，密码 `demo1234`

`pnpm seed` 会清空账本里的客户、订单、备注、推广、事实、弃单和生成任务，再灌入 40 人，并写入 `fixtures/demo-pet/abandoned.csv`。终端应打印 `seeded 40 customers`。人数对不上时，先停掉服务，再执行一次。销售改过的语言和公司地址也会回到演示初始值。

`fixtures/demo-pet/` 里的 CSV 已经提交。一般不用再跑 `node fixtures/demo-pet/generate.mjs`。

如果 `pnpm seed` 报错说 better-sqlite3 找不到 `.node` 文件，在仓库根目录执行 `pnpm rebuild better-sqlite3`，然后再 `pnpm seed`、`pnpm dev`。

页面上可以这样核对：

1. 登录后侧栏是 Paws Demo。客户 40 人，西班牙语 16 人。
2. 打开 Anna Cole。有画像、订单和原来的备注，没有添加标签或添加备注的按钮。事实里能看到这条备注，状态是已确认。
3. 「挑选客户」保持沉睡召回。可触达 27，排除 5，并能看到调用次数。没配单价时写「费用还没配置」。
4. 点「开始生成」。标题变成「已写完」后，点「一键通过」，再点「模拟发送」，提示 27 封。
5. 复制 Anna 的信。正文里有 Anna，没有 `{{`，有 SAVE20，底部是 `123 Demo St, Austin, TX 78701`。
6. 场景改成弃购挽回，应是 4 人、可触达 3。如果把弃单清空，这里应写「还没有弃单数据」，而不是 0 人。

其他命令：

| 命令 | 作用 |
| --- | --- |
| `pnpm test` | 跑共享包和接口测试，含四个场景、事实、聊天、中途继续，以及一份 3000 人的临时库 |
| `pnpm build` | 各包做 TypeScript 检查；网页还会做一次生产构建 |
| `pnpm --filter api exec tsx src/smoke.ts` | 对当前账本走一遍登录、沉睡人数、生成和模拟发送。会在正在用的库里留下一场已发送的推广 |

要调用 DeepSeek，在启动后端的那个进程里设置，不要写进代码或仓库：

```bash
DEEPSEEK_API_KEY=你的钥匙 DEEPSEEK_MODEL=deepseek-chat UNIT_PRICE_CENTS=3 pnpm --filter api dev
```

`DEEPSEEK_MODEL` 不写时用 `deepseek-chat`。`UNIT_PRICE_CENTS` 不写时，页面显示费用还没配置。只写在 `.env` 里不会生效，程序不读取这个文件。要固定「今天」，同样加在进程上，例如 `APP_NOW=2026-11-01`。

## 4. 以后接着改时要注意的地方

改动落在现有的 `apps/web`、`apps/api`、`packages/shared`。不要按 `docs/02-技术方案与目录结构.md` 去新建那里还没有的目录。

| --- | --- |
| `apps/web/src/App.tsx` | 客户、导入、店铺、挑选、推广都在这一个文件里 |
| `apps/web/src/api.ts` | 请求和前端类型 |
| `apps/api/src/app.ts` | 接口。生成、继续、重写一封、事实确认、弃单和聊天都从这里进来 |
| `apps/api/src/audience.ts`、`audience-rules.ts` | 四个场景、单独写还是共用、费用 |

| `apps/api/src/imports/abandoned.ts` | 弃单。确认导入会换掉这家店的全部弃单 |
| `apps/api/src/chat/gorgias.ts` | Gorgias CSV。分类在 `generation/model.ts` 的 `classifyQuote` |
| `apps/api/src/facts/sync.ts`、`facts/phrases.ts` | 标题抽词和备注转成事实 |
| `apps/api/src/generation/run.ts` | 异步写信、共用底稿、中途继续、只重写一封 |

| `apps/api/src/templates.ts` | 本地信纸。优惠句固定 20% off |
| `apps/api/src/db.ts` | 建表。没有通用迁移工具 |
| `apps/api/src/seed.ts` | 清空后灌入演示数据，并写入弃单和事实 |
| `packages/shared/src/index.ts` | 校验、占位符、简报、遮盖联系方式 |
| `fixtures/demo-pet` | 演示客户、订单、弃单和备注 |

`generation/index.ts`、`facts/index.ts`、`chat/index.ts` 不是实现。接口从具体文件导入。改行为时改旁边的 `run.ts`、`sync.ts`、`gorgias.ts`，不要只改这三个入口文件。

### 临时方案，以后要换掉

1. **信纸上的优惠句。** `generateTemplate` 看到折扣码就写 20% off，不翻译中文意图。接上稳定的 DeepSeek 之后，应让模型按意图写优惠；没钥匙、超时或解析失败时仍用这张信纸。不要接 OpenAI。
2. **`/health` 里的另外两把钥匙。** 返回里还有 OpenAI 和豆包是否配置。产品决定是 DeepSeek，失败再用信纸。
3. **添加备注和添加标签的接口。** 页面按钮已经去掉，`POST /api/v1/customers/:id/notes` 和 `/tags` 还在。若确定不再手写，把这两个接口也删掉，并改掉还在调用它们的测试。
4. **标题抽词。** `repeatedTitlePhrases` 会留下 `Litter` 这类普通词。以后可以换成更稳的说法，或让忽略之后不再被导入重新建出来。
5. **忽略没有墓碑。** 事实状态只有待确认和已确认。忽略是 `DELETE`。再次同步会把同一句标题加回来。
6. **挑选页的费用。** 次数是筛选后的整份名单，取消勾选不会重算。若销售会先大批勾掉人再看费用，要在勾选变化时再算一次。
7. **退订。** 链接这一版打不开成功页，也不写已退订。登录校验已经放行 `/u/`。
8. **任务级的 writer。** `generation_jobs.writer` 表示这场打算用模型还是信纸。某一封失败后，那一行草稿的 `writer` 才是 `template`。看「这封是谁写的」以草稿为准。

### 改代码时容易踩的地方

- **旧账本不会自己长出新列。** `CREATE TABLE IF NOT EXISTS` 不改已经存在的表。四张画像表若建表语句里没有 `CHECK`，或事实表的检查里没有 `unclassified`，启动时会删掉重建。草稿表只补了 `writer` 和 `generation_ok` 两列。改完表结构后，在 `apps/api` 目录执行 `pnpm seed`。
- **数据库路径跟着进程的当前目录。** 默认文件是 `apps/api/data/app.db`，因为 `pnpm --filter api` 的工作目录是 `apps/api`。从仓库根目录直接启动后端，会另开一本空库。这个文件已被 git 忽略。
- **同一时间只跑一个后端。** SQLite 开着外键和 WAL。生成进行时再开一个进程，会锁库。写信在进程内存里记着「正在跑」的任务，重启后这些任务变成「中途停下」，要点「继续写剩下的」。
- **`pnpm seed` 会删掉整本账本再重建演示店。** 手里正在看的导入、改过的语言、公司地址和推广都会没。
- **流程测试不要放进同一个 `tsx` 进程。** `outreach.flow.test.ts`、`import.flow.test.ts`、`store.flow.test.ts`、`profile.flow.test.ts`、`scale.flow.test.ts` 各自在导入数据库模块之前设置 `DATABASE_PATH`。`apps/api/package.json` 里它们是分开的 `tsx --test`。并进前一条命令会共用一本库。三千人测试用临时库，不要指到 `apps/api/data/app.db`。
- **生成是异步的。** `POST .../generate` 在 2 秒内返回，当时草稿往往还是 0。测试和 `smoke.ts` 要轮询到 `job.status === done`。失败的草稿 `generation_ok` 为 0，同一轮循环不会反复重试；「继续写剩下的」会先删掉这些失败行再补写。已经写好的（`generation_ok` 为 1）不会被重写。
- **共用底稿按组复制。** 组键是语言、国家、场景、消费层级、主要品类，不含天数。底稿里不要写死某一个商品标题或天数，否则同组的人会看到别人的商品。查找已有底稿时用 `LIMIT 1`。不要改回「每次把这一场的草稿全部读进内存再比较」，三千人会变得很慢。
- **弃单日期必须落在「今天」往前 1 到 7 天。** 演示行在 2026-10-26 到 2026-10-30。把 `APP_NOW` 改掉又不改这些日期，弃购挽回会是 0 人。没上传时要保持「还没有弃单数据」。
- **不要用打过码的邮箱替换 40 位演示客户。** Anna 仍是 `anna.cole@example.com`。Gorgias 样例里的 `customer0001***@example.com` 对不上她，会计入「对不上」。测试要用 Anna 的真实邮箱。
- **订单 CSV 一行是一件商品。** 按订单 `Name` 合并。客户和订单用小写邮箱关联。订单金额先读 `Total`；没有总金额时，把各行 `Lineitem price` 相加，不乘数量。金额用整数「分」，显示时再除以 100。
- **查询要带 `store_id`。** 现在只有一家演示店。能否生成和发送走现有的 `isEmailEligible`，不要另写一套同意条件。
- **接口用驼峰，账本列用蛇形。** `GET /api/v1/store` 返回 `companyAddress`。`GET /api/v1/auth/me` 仍返回 `company_address`，网页只用了其中的店名。新增字段时同时改 `apps/api/src/app.ts` 和 `apps/web/src/api.ts`。
- **新增的请求体用 `.strict()`。** 多一个字段会 400。审核只接受 `approve`。公司地址去掉空白后长度要在 1 到 300，数据库触发器也会拒绝更长或空白的地址。
- **没有正文的 POST 不要加 `Content-Type: application/json`。** `api.ts` 只在有正文时加这个头。生成、继续、一键通过、模拟发送、重写这一封都是空正文。
- **占位符在复制和发送时才填。** 白名单在 `packages/shared`。公司地址从店铺表现读，所以旧草稿会用上新地址。模型若漏了占位符，`compose.ts` 会补上 `{{first_name}}`、`{{unsubscribe_url}}`、`{{company_address}}`。
- **遮盖联系方式的电话规则也会碰上像日期的数字。** 备注先遮盖再送进简报。调整规则时，种子备注和导入备注要一起看。
- **中文事实不进外语正文。** 含汉字的已确认原话留在中文对照和定制要点里。拉丁字母的原话可以出现在外语正文。待确认的事实两边都不进。
- **网页开发服务只监听本机的 IPv6。** 用 `http://localhost:5173` 打开。`127.0.0.1:5173` 连不上。接口 `http://127.0.0.1:3000` 可以。
