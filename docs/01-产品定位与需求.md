# 01 产品定位与需求

> 版本：V0.1（第一阶段）
> 状态：规划稿，等待负责人确认
> 标记约定见 [README](./README.md#状态标记约定)

## 1. 产品定位

### 1.1 一句话定位（已确认）

**面向中国跨境中小卖家（以独立站为主）的 AI 定向营销助手。**

### 1.2 展开说明（建议，待确认）

帮助独立站卖家利用自己店铺已有的客户和订单数据，**找出值得营销的客户群体**，并用 AI **为每个群体生成符合目标市场语言习惯的营销内容**。卖家审核后，把客户名单和内容导出到现有的邮件或广告工具中使用。

第一阶段的产品边界：

- 产品负责**“找对人”和“写对话”**：分群和生成内容。
- 产品**不负责“发出去”**：发送仍由卖家已经在用的工具完成，例如 Shopify Email、Klaviyo、Mailchimp。
- 所有 AI 产出必须经过卖家审核才能导出，产品不会自动对外发送任何内容。

## 2. 目标用户

### 2.1 核心用户画像（已确认方向，细节建议待确认）

| 维度 | 描述 |
| --- | --- |
| 身份 | 中国跨境中小卖家，以**独立站**为主要销售渠道 |
| 团队规模 | 1～20 人，通常没有专职的海外营销或数据分析人员（建议，待确认） |
| 建站平台 | Shopify 为主，也包括 Shoplazza（店匠）、Shopline、WooCommerce 等（建议，待确认） |
| 目标市场 | 欧美英语市场优先（建议，待确认） |
| 语言能力 | 日常工作语言是中文，能读懂英文，但写地道的营销文案比较吃力 |
| 已有工具 | 建站平台后台、Excel、可能已经开通邮件营销工具，但用得比较浅 |

### 2.2 用户痛点（建议，待确认）

1. **数据在手，不会用**：店铺后台有订单和客户数据，但不知道该给哪些客户、在什么时候、推送什么内容。
2. **营销靠群发**：常见做法是给全部客户发同一封促销邮件，效果差，还会提高退订率和进垃圾箱的概率。
3. **英文文案成本高**：自己写不够地道；请外籍文案太贵；直接用通用 AI 工具又要反复写提示词，而且不了解自己的店铺和客户。
4. **复购和老客运营薄弱**：独立站获客成本高，但对首单客户的二次转化、沉睡客户的召回缺少系统化的方法。

### 2.3 核心使用场景（建议，待确认）

一位 Shopify 卖家希望在下周做一次老客营销：

1. 从店铺后台导出客户和订单 CSV，上传到产品中。
2. 在“客户分群”页面看到系统预置的分群，以及每个分群的人数和特征，例如“首单后 30～60 天未复购：312 人”“90 天以上未购买的沉睡客户：1,208 人”。
3. 选择“首单后未复购”分群，创建一次营销活动，用中文填写营销目标，例如“推新品，配合 9 折券，促进第二单”。
4. AI 生成 3 个版本的英文邮件，包括标题、预览文本和正文，每个版本附有中文对照。
5. 卖家对比、修改，然后把其中一版标记为“已通过”。
6. 导出两份文件：该分群中**已同意接收营销**的客户名单 CSV，以及通过审核的邮件内容。导入邮件工具后发送。

## 3. 第一阶段功能范围

### 3.1 核心功能清单（建议，待确认）

| 编号 | 功能 | 需求内容 | 优先级 |
| --- | --- | --- | --- |
| F1 | 店铺与数据导入 | 创建店铺；上传 Shopify 标准导出格式的客户 CSV 和订单 CSV；先预览和校验，确认后入库；记录每个导入批次和错误行。 | P0 |
| F2 | 客户画像 | 按客户汇总首购和末购时间、订单数、累计消费、客单价、购买过的品类、是否同意营销、国家/地区。 | P0 |
| F3 | 预置分群 | 提供 5～6 个独立站常用分群（见 3.2），显示人数、占比和关键特征。 | P0 |
| F4 | 自定义分群 | 通过有限的条件组合（字段 + 比较符 + 值，条件之间用“且”连接）创建分群，并实时预览人数。 | P1 |
| F5 | 营销活动创建 | 选择分群，填写营销目标（中文）、渠道（第一阶段只做邮件）、目标语言、语气风格、优惠信息。 | P0 |
| F6 | AI 内容生成 | 按分群特征和营销目标生成 N 个版本（默认 3 个）的邮件，包括标题、预览文本、正文；附中文对照；可以对单个版本重新生成。 | P0 |
| F7 | 内容审核 | 卖家可以编辑每个版本，并标记为通过或驳回；只有通过的内容可以导出。 | P0 |
| F8 | 合规检查 | 生成后自动检查：是否包含退订说明的占位符、是否出现夸大或违禁表述、是否残留未替换的占位符；检查结果以提示形式展示。 | P0 |
| F9 | 导出 | 导出分群名单 CSV（**默认只包含同意营销的客户**），以及已通过内容的 HTML 或纯文本；每次导出都留有记录。 | P0 |
| F10 | 生成记录追溯 | 每条 AI 内容都记录所用模型、提示词模板版本、输入的分群特征摘要和生成时间。 | P0 |
| F11 | 简单登录 | 单个工作区，账号密码登录，保护所有业务接口。 | P1 |

### 3.2 预置分群（建议，待确认）

| 分群 | 判定口径（默认值可以在配置中调整） | 典型营销目标 |
| --- | --- | --- |
| 新客首单未复购 | 只有 1 笔订单，且首单距今 30～60 天 | 促进第二单 |
| 高价值客户 | 按 RFM 打分排在前 20%，或累计消费排在前 10% | 新品优先体验、VIP 回馈 |
| 沉睡客户 | 最后一次购买距今超过 90 天，且历史订单数 ≥ 1 | 召回 |
| 流失风险客户 | 历史订单数 ≥ 2，且距上次购买的时间超过其平均复购间隔的 1.5 倍 | 挽留 |
| 折扣敏感客户 | 历史订单中有 50% 以上使用了折扣码 | 促销活动 |
| 品类购买者 | 购买过指定品类或商品（创建时选择） | 交叉销售、关联推荐 |

### 3.3 第一阶段明确不做

- 不直接发送邮件、短信或 WhatsApp 消息，不对接发送服务商。
- 不通过 API 实时同步店铺数据（第一阶段只做 CSV 导入，API 对接放到第二阶段）。
- 不做弃购挽回（标准 CSV 导出中不包含弃购数据）。
- 不做广告投放，不对接 Meta 或 Google 广告账户。
- 不做营销效果回收和归因分析。
- 不做多工作区、多成员权限或计费。
- 不做 AI 自动决策，例如自动选择分群或自动定时发送。

## 4. 关键原则

1. **个人信息不进入大模型**：发送给大模型的只有分群层面的聚合特征（人数、平均客单价、热门品类、主要国家等）和卖家填写的营销目标，不发送客户姓名、邮箱、地址等个人信息。
2. **人审后才能导出**：AI 产出默认是草稿状态，只有卖家标记为“已通过”后才能导出。
3. **默认合规**：导出名单时默认排除未同意营销的客户；卖家必须手动勾选并看到风险提示后，才能包含这些客户。
4. **可追溯**：任何一条内容都能追溯到它所用的分群快照、提示词版本和模型。
5. **“没有数据”不等于“没有客户”**：字段缺失（例如没有品类信息）时，界面要明确提示“数据不足”，不能显示为 0 人。

## 5. 成功指标（建议，待确认）

| 指标 | 第一阶段目标 |
| --- | --- |
| 从上传 CSV 到导出第一份可用的营销内容 | 新用户在 15 分钟内完成 |

## 6. 待确认事项

| 事项 | 当前建议 | 需要确认的内容 |
| --- | --- | --- |
| 建站平台优先级 | 先支持 Shopify 导出格式，其他平台通过“字段映射”兼容 | 种子用户主要使用哪个平台？是否需要第一阶段就支持店匠或 Shopline 的原生格式？ |
| 营销渠道 | 第一阶段只做邮件 | 是否需要同时生成社媒帖子、WhatsApp 消息或广告文案？ |
| 目标语言 | 英语优先，架构上支持多语言 | 第一阶段是否需要德语、法语、西班牙语、日语？ |
| 大模型供应商 | 使用兼容 OpenAI 的接口，可以切换到 DeepSeek、通义千问或 OpenAI | 首选哪家？是否有成本上限？部署在国内还是海外？ |
| 部署形态 | 先由团队自己部署一套演示环境，后续再做 SaaS | 第一阶段是否需要对外开放注册？ |
| 数据合规 | 只把聚合特征发给大模型；名单默认只导出同意营销的客户 | 是否需要数据删除功能、数据保留期限，以及与 GDPR 相关的说明页面？ |
| 品牌信息 | 店铺设置中填写品牌名称、品牌语气和主营品类，作为生成内容的上下文 | 是否需要上传品牌规范或历史优秀邮件作为参考？ |
