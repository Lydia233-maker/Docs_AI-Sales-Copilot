# 01 产品定位与需求

> 版本：V1（第一版，可试用版）
> 状态：规划稿，等待负责人确认后开工
> 标记约定：**已确认**表示负责人已经明确的决定；**建议**表示本文提出的默认方案，负责人没有反对时按此执行；**待确认**表示开工前或对应任务开始前需要回答的问题。

## 1. 产品定位（已确认）

**面向中国跨境中小卖家的 AI 定向营销助手：导入独立站客户和订单数据，自动给海外客户分群，用 AI 按人群、按语言批量生成地道的营销邮件和 WhatsApp 文案，一键发送并追踪复购转化。**

产品目标：**做成能卖的产品，而不只是作品集。** 第一版完成后，要能交给 3～5 个真实卖家试用。所以“真实数据能导进来”“合规”“结果能证明价值”的优先级，高于功能的数量。

## 2. 目标用户

### 2.1 用户画像（已确认）

| 维度 | 描述 |
| --- | --- |
| 身份 | 跨境电商中小卖家的**店主或运营** |
| 销售渠道 | 第一版只面向**独立站**（Shopify） |
| 工作方式 | **批量推送**，不是一对一销售跟进 |
| 目标市场 | 默认欧美 |
| 品类 | 不限；演示数据使用宠物用品 |
| 语言 | 工作语言是中文，界面全部用中文 |

### 2.2 用户痛点（建议）

1. **数据在手，不会用**：Shopify 后台有客户和订单数据，但不知道该给谁、在什么时候、发什么内容。
2. **只会群发**：给所有客户发同一封邮件，效果差，退订率高，容易进垃圾箱。
3. **外语文案难写**：英语和西班牙语写不地道；通用 AI 工具不了解店铺和客户，每次都要重写提示词。
4. **Klaviyo 等工具太重**：英文界面，概念多，按联系人数量收费，中小卖家学不会、用不起。
5. **错过海外营销节点**：对黑五、斋月、亡灵节等节日的时间和营销习惯不熟，经常临时才想起来。

### 2.3 与现有工具的差异（已确认）

1. 运营**用中文写活动意图**。
2. AI 按客户的**国家和语言**生成外语文案，同时提供中文对照，方便运营审核。
3. **中文界面**。
4. **自动提示海外营销节点**，例如黑五、斋月。
5. **比 Klaviyo 更简单**，专门面向中国卖家。

## 3. 第一版范围

### 3.1 平台与数据（已确认）

- 只支持独立站，按 **Shopify 客户和订单的 CSV 导出格式**导入。
- 不支持 Amazon、Temu、SHEIN（这些平台的卖家不能主动营销）。Shopee、Lazada、TikTok Shop 以后再考虑。
- 数据接入做成**可替换的接口**：以后接入 Shopify API，并考虑上架 Shopify 应用市场。

建议：

- 必须导入：客户 CSV、订单 CSV。
- 可选导入：弃单（abandoned checkouts）CSV，用于“弃购挽回”；商品 CSV，用于把商品对应到品类（订单导出中没有品类字段）。
- 没有导入弃单 CSV 时，“弃购挽回”分群显示“未导入弃单数据”，而不是 0 人。

### 3.2 渠道（已确认）

| 渠道 | 第一版做法 |
| --- | --- |
| 邮件 | 可以真实接入发送接口，但**默认“模拟发送”**，不需要邮件服务账号 |
| WhatsApp | 按客户生成文案并**导出**，不自动发送 |
| 短信 | 以后再做 |

### 3.3 语言（已确认）

- 文案语言：**英语、西班牙语**。
- 每份文案都附**中文对照**，供运营审核。

客户语言的判定规则（建议）：

1. 优先读取客户标签中的 `lang:en` 或 `lang:es`。
2. 没有标签时按国家判断：西班牙及拉美西语国家（ES、MX、AR、CO、CL、PE 等）为西班牙语，其他国家默认英语。
3. 运营可以在店铺设置中调整“国家到语言”的映射。

### 3.4 营销场景（已确认场景，口径为建议）

| 场景 | 默认口径（店铺设置中可调） | 说明 |
| --- | --- | --- |
| 复购提醒 | 客户最近一次购买某个消耗品品类后，距今天数落在“该品类复购周期 ±7 天”范围内 | 需要为品类配置复购周期；演示数据：猫粮/狗粮 30 天，猫砂 21 天，零食 14 天 |
| 沉睡召回 | 最后一次购买距今 **≥ 60 天**（已确认），且历史订单数 ≥ 1 | 召回 |
| 首单转二单 | 只有 1 笔订单，且首单距今 7～30 天 | 促成第二单 |
| 弃购挽回 | 弃单发生在最近 1～7 天内，且之后没有成功下单 | 需要导入弃单 CSV |
| 活动分层推送 | 按**国家、语言、消费层级、品类偏好**组合筛选 | 消费层级按累计消费分为高（前 20%）、中（20%～60%）、低（其余） |

### 3.5 核心功能清单（建议）

| 编号 | 功能 | 需求内容 | 优先级 |
| --- | --- | --- | --- |

| F2 | 店铺设置 | 品牌名、品牌语气、发件人名称、回复邮箱、**公司实际地址**（营销邮件的法律要求）、币种、时区、国家与语言映射、品类复购周期 | P0 |
| F3 | 数据导入 | 上传 Shopify 客户、订单、弃单、商品 CSV；先预览和逐行校验，再确认入库；重复导入时按 ID 更新；记录导入批次 | P0 |
| F4 | 客户列表与画像 | 汇总每位客户的订单数、累计消费、首购和末购时间、消费层级、品类偏好、语言、营销同意状态 | P0 |
| F5 | 场景分群 | 3.4 中 5 个场景的人群，显示人数、可触达人数（已同意营销）、语言分布和国家分布 | P0 |
| F6 | 营销节点提醒 | 首页展示未来 45 天内的海外营销节点，包括建议的预热开始日期和推荐场景，可以一键创建活动 | P0 |
| F7 | 活动创建 | 选择场景和分层条件、渠道（邮件 / WhatsApp）、用中文写活动意图、填写优惠信息（折扣码等） | P0 |

| F9 | 文案检查 | 规则检查（退订链接、占位符、长度、违禁或夸大表述、语言是否正确）加 AI 检查（语气和误译提示）；存在严重问题时不能通过审核 | P0 |
| F10 | 审核 | 编辑文案，并标记为通过或驳回；每种语言至少有 1 个通过的版本，活动才能发送或导出 | P0 |
| F11 | 邮件发送 | 发送前确认收件人数和被排除的人数（附原因）；默认模拟发送；可以配置真实发送；每封邮件都带个人专属的退订链接 | P0 |
| F12 | WhatsApp 导出 | 按客户渲染个性化文案，导出 CSV（手机号、姓名、语言、文案、wa.me 链接） | P0 |
| F13 | 退订 | 公开的退订页面，一键退订；退订后立即更新客户的营销同意状态，以后不再发送 | P0 |
| F14 | 转化追踪 | 活动报表：发送、送达、打开、点击、退订、转化客户数、转化金额、复购率；转化在导入新订单后自动计算 | P0 |
| F15 | 客户数据删除 | 删除单个客户（彻底清除个人信息），或清空整个店铺的数据；保留不含个人信息的操作日志 | P0 |
| F16 | 对照组 | 活动可以设置随机留出 10% 的客户不发送，用于比较转化率，向卖家证明效果 | P1 |

### 3.6 营销节点（建议）

内置节点数据（可维护的数据文件，按年更新）：

- 欧美通用：情人节、复活节、母亲节、父亲节、返校季、万圣节、黑色星期五、网络星期一、圣诞节、节礼日、新年。
- 西语市场：三王节、墨西哥 Hot Sale、亡灵节。
- 穆斯林人口较多的市场：斋月、开斋节（日期每年不同，需按年维护）。
- 品类节点（演示用宠物用品）：国际宠物日（4 月 11 日）、国际猫咪日（8 月 8 日）、国际狗狗日（8 月 26 日）。

每个节点包含：名称（中文和英文）、日期、适用国家或语言、建议的预热天数、推荐场景，以及一句中文营销提示。

### 3.7 第一版明确不做

- Amazon、Temu、SHEIN、Shopee、Lazada、TikTok Shop 的数据接入。
- Shopify API 实时同步（只预留接口）。
- WhatsApp 自动发送、短信。
- 可视化邮件编辑器、复杂的自动化流程编排。
- 广告投放。
- 对外开放注册和计费（试用账号由管理员创建）。

## 4. 合规要求（已确认，必须写进验收标准）

1. **营销邮件必须包含退订链接**：缺少退订链接的文案不能通过审核，也不能发送；每封邮件的退订链接都是该收件人专属的。
2. **只向已同意接收营销的客户发送**：以导入数据中的营销同意字段为准；退订、已删除的客户自动排除。
3. **客户数据可以删除**：支持删除单个客户和清空店铺，删除后无法再查到该客户的个人信息。

补充原则（建议）：

- **发给大模型的数据不包含客户个人信息**：只发送人群层面的统计特征（人数、主要国家、热门品类、平均客单价等）和运营写的活动意图；姓名、邮箱、手机号只在本地渲染占位符时使用。
- WhatsApp 导出同样只包含已同意营销、且手机号有效的客户。第一版用 Shopify 的“短信营销同意”（Accepts SMS Marketing）字段作为依据（**待确认**）。
- 真实发送邮件前，店铺设置中必须填写公司实际地址，并自动写入邮件页脚。

## 6. 成功标准（建议）

| 指标 | 目标 |
| --- | --- |
| 试用上手 | 卖家用自己的 Shopify 导出数据，在 20 分钟内完成“导入 → 分群 → 生成 → 审核 → 模拟发送” |
| 试用规模 | 3～5 个真实卖家试用，每家至少完成 1 次活动 |
| 文案可用 | 不修改或只做少量修改就通过审核的文案版本占比 ≥ 60% |
| 价值证明 | 至少 1 个卖家通过真实发送加对照组，看到可比较的转化数据 |

## 7. 待确认事项

| 事项 | 当前建议 | 需要确认的内容 |
| --- | --- | --- |
| 真实邮件发送方式 | 通用 SMTP（任何邮件服务商都能接），并预留 Resend 等 API 适配器 | 试用卖家常用哪家邮件服务？ |
| WhatsApp 营销同意依据 | 使用 Shopify 的“短信营销同意”字段 | 是否接受？还是要求卖家在客户标签中单独标注？ |
| 打开和点击追踪 | 模拟发送时生成模拟数据；真实发送时，用点击跳转链接统计点击，打开像素为可选 | 部署环境是否有公网域名（真实追踪需要）？ |

| 部署 | 一台云服务器 + Docker，每个试用卖家一个账号 | 部署在国内还是海外？是否需要备案？ |
| 复购周期 | 按品类配置，演示数据内置宠物用品的默认值 | 是否需要按商品（SKU）配置？ |
| 试用数据 | 先用演示数据开发，试用前用真实导出文件验证 | 能否提前拿到 1 份脱敏的真实 Shopify 导出文件，用于核对字段？ |
