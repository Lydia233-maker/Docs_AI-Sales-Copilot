# 01 产品定位与需求

> 版本：V1（第一版，可试用版）
> 状态：需求已与负责人逐条确认；技术细节等待确认后开工
> 标记约定：**已确认**表示负责人已经明确的决定；**建议**表示本文提出的默认方案，负责人没有反对时按此执行；**待确认**表示开工前或对应任务开始前需要回答的问题。

## 1. 产品定位（已确认）

**面向中国跨境中小卖家的 AI 定向营销助手：销售或运营选中一批独立站客户，系统根据每个客户的画像（购买记录、偏好、国家、语言、销售备注）为每人生成一份独立的推广文案，审核后发出，并追踪复购转化。**

- **我们的产品卖给谁**：跨境卖家，即店主、销售、运营。这是一款 B 端（To B）工具。
- **卖家用它做什么**：给**自己的 C 端顾客**（海外个人消费者）做定制化的营销推广。
- **核心不是群发**：同一批客户中，每个人收到的内容都不一样。

产品目标：**做成能卖的产品，而不只是作品集。** 第一版完成后，交给 3～5 个真实卖家试用。

## 2. 用户与客户

### 2.1 使用者：卖家团队（已确认）

| 维度 | 描述 |
| --- | --- |
| 角色 | 跨境中小卖家的**销售、运营或店主** |
| 工作方式 | 一个人跟进**一批**客户，其中既有熟悉的老客户，也有还没打过交道的独立站客户 |
| 销售渠道 | 第一版只面向**独立站**（Shopify） |
| 工作语言 | 中文，界面全部用中文 |

### 2.2 收到推广的人：卖家的 C 端顾客（已确认）

- 海外个人消费者，默认在欧美。
- 语言为英语或西班牙语。
- 第一版不针对批发或企业买家。客户资料中保留“客户类型”（零售 / 批发）字段，由销售手动标注，以后再支持 B 端买家的文案写法。

### 2.3 痛点（建议）

1. **群发没效果**：给所有客户发同一封邮件，打开率低、退订多；但一个个手写又写不过来。
2. **销售对客户的了解用不上**：销售知道“这位客户养了两只猫”“上次抱怨过物流慢”，但这些信息散落在脑子里或表格里，写文案时用不上。
3. **外语写不地道**：英语、西班牙语写不好；通用 AI 工具不了解店铺和客户，每次都要重写提示词。
4. **Klaviyo 等工具太重**：英文界面、概念多、按联系人收费，而且擅长的是“按群自动化”，不是“按人定制”。
5. **错过海外营销节点**：对黑五、斋月、亡灵节等节日的时间和习惯不熟。

### 2.4 差异化（已确认）

1. 运营**用中文写推广意图**。
2. AI 根据**每个客户的画像**，用他的语言写**专属文案**，并提供中文对照，方便审核。
3. 销售补充的信息和备注会被用来写文案。
4. **中文界面**。
5. **自动提示海外营销节点**，例如黑五、斋月。
6. 比 Klaviyo **更简单**，专门面向中国卖家。

## 3. 核心流程（已确认）

```
导入数据 ──► 完善画像（销售补充信息和备注）──► 挑选客户（场景筛选 / 条件筛选 / 手动勾选）
   ──► 填写推广意图（中文）──► 逐个客户生成专属文案 ──► 审核（问题优先，其余可一键通过）
   ──► 发送（系统逐封发邮件 / 复制后自己发 / WhatsApp 复制、打开或导出）──► 追踪转化
```

一个典型场景：

1. 运营小王从 Shopify 后台导出客户和订单 CSV，导入产品。
2. 她在几位熟悉的老客户资料上补充备注，例如“养了两只布偶猫，喜欢无尘猫砂”“上次反馈物流慢，已补偿”。
3. 首页提示“黑五还有 30 天，建议 11 月 10 日开始预热”。她用“消费层级：高”加“品类：猫用品”筛出 86 位客户，又手动勾选了 4 位，共 90 人。
4. 她用中文填写推广意图：“黑五老客专享 8 折，主推猫砂和猫粮，强调囤货划算”。
5. 系统显示：其中 62 人信息充足，将逐个定制；28 人信息较少，将按小群生成；预计调用模型 70 次，以及大致费用。她点击“开始生成”。
6. 几分钟后，90 份文案生成完毕。美国客户收到英语文案，墨西哥客户收到西班牙语文案，每份都有中文对照。那位“布偶猫”客户的文案提到了无尘猫砂；那位“物流慢”的客户的文案中提到了物流已经改进。
7. 列表顶部是 5 份需要重点看的文案（2 份检查不通过、3 份由小群方式生成）。她逐一修改，其余的一键通过。
8. 她让系统逐封发送邮件（当前为模拟发送），对其中 3 位熟客，她复制文案后自己通过 WhatsApp 发送。
9. 一周后再次导入订单，报表显示有 14 位客户下单。

## 4. 第一版范围

### 4.1 数据（已确认）

- 只支持独立站，按 **Shopify 客户和订单的 CSV 导出格式**导入。不支持 Amazon、Temu、SHEIN；Shopee、Lazada、TikTok Shop 以后再考虑。
- 数据接入做成**可替换的接口**，以后接入 Shopify API，并考虑上架 Shopify 应用市场。
- 建议：必须导入客户 CSV 和订单 CSV；可选导入弃单 CSV（用于“弃购挽回”）和商品 CSV（把商品对应到品类）。

### 4.2 客户画像（已确认）

画像由两部分组成：

| 来源 | 内容 |
| --- | --- |
| 导入数据自动计算 | 购买过的商品和品类、订单数、累计消费、客单价、首购和末购时间、消费层级、国家、语言、营销同意状态、Shopify 标签 |
| 销售手动补充 | **备注**（自由文本，可以有多条，带时间）、偏好标签（如“布偶猫”“无尘猫砂”“价格敏感”）、客户类型（零售 / 批发）、语言（修正自动判断的结果） |

- 语言自动判断（建议）：优先读取 `lang:en` 或 `lang:es` 标签；没有标签时按国家判断（西班牙及拉美西语国家为西班牙语，其他为英语）；销售可以手动修正。
- **备注隐私提醒**（已确认）：备注会作为写文案的参考发给 AI。系统检测到备注中有邮箱、电话、详细地址等信息时，会提醒销售，并在发给 AI 前自动遮盖。

### 4.3 挑选客户（已确认）

三种方式可以组合使用：

1. **场景筛选**（口径为建议，店铺设置中可调）：

| 场景 | 默认口径 |
| --- | --- |
| 复购提醒 | 最近一次购买某个消耗品品类后，距今天数落在“该品类复购周期 ±7 天”范围内（演示数据：猫粮/狗粮 30 天，猫砂 21 天，零食 14 天） |
| 沉睡召回 | 最后一次购买距今 ≥ 60 天（已确认） |
| 首单转二单 | 只有 1 笔订单，且首单距今 7～30 天 |
| 弃购挽回 | 弃单发生在最近 1～7 天内，且之后没有下单（需要导入弃单 CSV） |

2. **条件筛选**：国家、语言、消费层级（高 / 中 / 低）、品类偏好、偏好标签、客户类型、是否有备注。
3. **手动勾选**：在客户列表中勾选或去掉个别客户。

- **单批上限默认 200 人**（已确认），管理员可以调整。
- 没有同意接收营销的客户也可以被选中，以便销售查看；但在发送环节会被自动排除，并在生成前提示“其中 N 人未同意接收营销，不会生成文案”。

### 4.4 生成文案（已确认）

| 客户情况 | 生成方式 |
| --- | --- |
| **信息充足**：订单数 ≥ 2，或者有销售备注或偏好标签（建议的口径） | **逐个定制**：每人调用一次模型，根据他的画像和推广意图写专属文案 |
| **信息很少**：只有 1 笔订单，且没有备注和偏好标签 | **小群方式（退路）**：按“语言 + 国家 + 场景 + 消费层级 + 主要品类”分成小群，每个小群生成一份，再填入姓名、上次购买的商品等个人信息 |

- 每份文案都包含**外语原文**（英语或西班牙语，按客户语言）和**中文对照**。
- 邮件包含标题、预览文本和正文；WhatsApp 是一条短消息。销售选择本次要生成的渠道（邮件、WhatsApp 或两者）。
- **发给 AI 的数据不包含姓名、邮箱和手机号**：文案中用占位符代替，发送或复制时在本地填回。
- 每份文案都标注生成方式（逐个定制 / 小群方式）和使用的模型。
- 可以对单份文案点击“重新生成”或“用高质量模型重写”。
- 生成在后台进行，界面显示进度；单个客户生成失败不影响其他客户，失败的可以单独重试。

### 4.5 审核（已确认）

- 每份文案都可以查看、修改，并标记为通过或驳回。
- 列表**把需要重点看的排在最前面**：检查不通过的、信息不足的、由小群方式生成的、由备用模型或模板生成的。
- 其余文案可以**一键全部通过**（检查不通过的不会被一键通过）。

### 4.6 发送（已确认）

| 方式 | 说明 |
| --- | --- |
| 系统逐封发送邮件 | 每封内容都不同；**默认模拟发送**，不需要邮件服务账号；配置邮件服务后可以真实发送 |
| 复制后自己发 | 每份文案都有“复制”按钮，复制的是已填入个人信息的最终内容 |
| WhatsApp | 每份文案可以复制，也可以打开 wa.me 链接（已带上文案），或者批量导出 CSV；**不自动发送** |
| 短信 | 以后再做 |

### 4.7 营销节点（已确认）

首页展示未来 45 天内的海外营销节点，包括建议的预热开始日期和推荐场景，可以从节点直接开始挑选客户。建议内置的节点：

- 欧美：情人节、复活节、母亲节、父亲节、返校季、万圣节、黑色星期五、网络星期一、圣诞节、新年。
- 西语市场：三王节、墨西哥 Hot Sale、亡灵节。
- 穆斯林人口较多的市场：斋月、开斋节（按年维护日期）。
- 演示品类（宠物用品）：国际宠物日、国际猫咪日、国际狗狗日。

### 4.8 转化追踪（已确认）

- 推广报表显示：发送数、送达、打开、点击、退订、下单客户数、下单金额。
- 导入新的订单后自动计算转化。建议的口径：发送后 7 天内，收到文案的客户下单即计为转化；使用了推广折扣码的订单单独标注。
- 可以按“逐个定制”和“小群方式”分开比较转化率，用来证明定制的价值。
- 模拟发送产生的数据在报表中明确标注“模拟”。

### 4.9 第一版明确不做

- Amazon、Temu、SHEIN、Shopee、Lazada、TikTok Shop 的数据接入；Shopify API 实时同步（只预留接口）。
- 针对批发或企业买家的文案写法。
- WhatsApp 自动发送、短信。
- 自动化流程编排（如“下单后第 N 天自动发”）、可视化邮件编辑器、广告投放。
- 对外开放注册和计费（试用账号由管理员创建）。

## 5. 合规（已确认，必须写进验收标准）

1. **营销邮件必须包含退订链接**：缺少退订链接的文案不能通过审核，也不能发送；每封邮件的退订链接都是该收件人专属的。
2. **只向已同意接收营销的客户发送**：以导入数据中的营销同意字段为准；退订、已删除的客户自动排除。WhatsApp 第一版以 Shopify 的“短信营销同意”字段为依据（建议）。
3. **客户数据可以删除**：可以删除单个客户（包括销售备注），也可以清空整个店铺的数据。

补充：发给 AI 的数据不含姓名、邮箱、手机号，备注中的隐私信息会被遮盖；真实发送邮件前必须在店铺设置中填写公司实际地址，并写入邮件页脚。

## 6. 模型使用（已确认）

原则：**在保证质量的前提下，用最少、最划算的模型。**

1. **每个客户只调用 1 次模型**：一次请求同时返回外语文案和中文对照；小群方式下每个小群调用 1 次。
2. **默认只用 1 个低价模型**：从 GPT 的低价小模型和 DeepSeek 中选一个作为默认。**开工前用 10 个演示客户做一次对比**，比较质量、价格和速度后选定。
3. **默认不做 AI 检查**：每份文案都经过免费的规则检查；AI 检查只用于被标记的文案，或者销售点击“帮我检查”时。
4. **高质量模型只在需要时使用**：销售点击“用高质量模型重写”时才调用。
5. **备用和兜底**：默认模型失败时自动换另一个（GPT 和 DeepSeek 互为备用）；都失败时用模板。豆包接口兼容，可以通过配置切换。
6. **生成前显示预估**：显示本次的调用次数、预估 token 数和大致费用。
7. **没有任何 Key 时用模板生成**，保证可以离线演示。模板会使用画像中的商品、品类和场景，但不会理解备注。
8. **不使用 Cursor 作为模型接口。API Key 只从环境变量读取**，不写进代码、文档或日志。

## 7. 其他已确认事项

- 商品不限品类，演示数据使用宠物用品（复购周期清楚）。
- 默认市场为欧美；文案语言为英语和西班牙语，附中文对照。

## 8. 成功标准（建议）

| 指标 | 目标 |
| --- | --- |
| 试用上手 | 卖家用自己的 Shopify 导出数据，在 20 分钟内完成“导入 → 挑选 → 生成 → 审核 → 发送” |
| 文案可用 | 不修改或只做少量修改就通过审核的文案占比 ≥ 60% |
| 定制感 | 抽查逐个定制的文案，≥ 80% 能看出是写给这个客户的（提到他买过的商品、偏好或备注中的信息） |
| 成本 | 逐个定制 200 个客户的模型费用，在开工前的对比中测出，作为试用定价的依据 |
| 试用规模 | 3～5 个真实卖家试用，每家至少完成 1 次推广 |
