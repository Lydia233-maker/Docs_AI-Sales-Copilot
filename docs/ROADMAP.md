# 路线图

「已完成」表示当前代码里能运行的行为。「需求已确认、代码未做」来自 `docs/01-产品定位与需求.md`，不是新的猜测。没有单独的迭代排期：待确认。

## 已完成

- pnpm monorepo、React 页面、Fastify API、SQLite、共享 Zod 类型。
- 演示账号登录与 Cookie 会话。
- 灌入 40 位宠物用品客户及订单，算出语言、品类、消费层级、距今天数。
- 客户列表与档案；追加备注；添加偏好标签。
- 沉睡召回与全部客户两种挑选；生成前显示可触达与排除人数。
- 每人一封本地模板邮件（英语或西班牙语 + 中文对照）。
- 修改草稿、单份通过、一键通过、阻止缺少退订链接或公司地址的文案。
- 模拟发送，以及在页面上查看填好占位符的正文。
- 单元测试：简报拒绝姓名类字段、占位符白名单、资格判断、模板含标签、缺退订链接被阻止。
- 冒烟脚本覆盖登录到模拟发送。

## 开发中

## 未来规划

以下为需求文档中的完整版范围，当前仓库未实现。顺序未定。

- 页面上传 Shopify 客户 CSV、订单 CSV；可选弃单 CSV、商品 CSV。导入做成可替换接口，以后再接 Shopify API。
- 场景：复购提醒、首单转二单、弃购挽回。条件筛选与手动勾选。单批默认上限 200 人。
- 销售可改语言；客户类型（零售 / 批发）字段。批发文案写法明确后做。
- 真正的小群：按语言、国家、场景、消费层级、主要品类共用一封，再填入姓名和上次商品。
- 模型：每个客户或每个小群调用一次，同时返回外语和中文。需求暂定 DeepSeek，失败再试 OpenAI，再失败用模板。豆包可配置。生成前显示调用次数和费用。可单份重新生成，或用高质量模型重写。
- 开工前用 10 位演示客户对比模型。待有 API Key 后做（需求文档第 9 节）。
- 邮件预览文本；WhatsApp 短消息、wa.me、导出 CSV。不自动发送 WhatsApp。
- 真实邮件走 SMTP，默认仍是模拟发送。
- 退订页面，并立即排除该客户。
- 删除单个客户（含备注）和清空店铺。
- 首页展示未来 45 天营销节点，并可从节点开始挑选。
- 转化报表：发送、送达、打开、点击、退订、下单人数与金额。再次导入订单后按发送后 7 天归因。模拟数据要标注「模拟」。
- 试用部署：一台云服务器加 Docker，每个试用卖家一个账号（需求第 9 节）。地区待确认。

需求明确不做，代码里也没有：Amazon / Temu / SHEIN / Shopee / Lazada / TikTok Shop、WhatsApp 自动发送、短信、自动化流程编排、可视化邮件编辑器、广告投放、对外开放注册和计费。
