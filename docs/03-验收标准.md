# 03 验收标准

> 版本：V1（第一版，可试用版）
> 状态：规划稿，等待负责人确认后开工
> 前置文档：[01 产品定位与需求](./01-产品定位与需求.md)、[02 技术方案与目录结构](./02-技术方案与目录结构.md)

第一版是否完成，以本文档中的条目为准。每一条都标注了验证方式：**E2E**（tests/e2e 中的 Playwright 测试）、**API**（tests/e2e/api 中的接口测试）、**单测**（apps 内的 Vitest 测试）、**人工**（演示时人工检查）。Agent C 负责把标注为 E2E 和 API 的条目全部落实为自动化测试，并汇总到 `tests/e2e/acceptance/run.ts` 的报告中。

条目前缀：**G** 通用，**D** 数据，**S** 分群，**H** 营销节点，**M** 模型与文案，**R** 审核，**E** 发送与导出，**T** 追踪，**C** 合规（重点），**K** 安全与配置，**P** 试用就绪。

## 1. 通用标准（每个 PR 都必须满足）

- [ ] G1 在根目录执行 `pnpm install && pnpm build && pnpm test && pnpm lint` 全部通过。
- [ ] G2 所有测试在**离线且没有任何 API Key** 的环境中运行通过。
- [ ] G3 前后端交换的数据结构全部来自 `packages/shared`；apps 中没有重复定义接口类型（代码审查）。
- [ ] G4 子 Agent 的 PR 只修改自己负责的目录（CI 检查改动路径，规则见 04）。
- [ ] G5 后端对每个接口的响应都用 shared 中的 schema 校验；响应与 schema 不一致时，测试失败（API）。
- [ ] G6 卖家使用的界面文字全部为中文；外语只出现在文案内容本身，以及面向海外客户的退订页面（人工 + E2E 抽查）。

## 2. 数据导入（D）

- [ ] D1 上传 `fixtures/demo-pet/customers.csv` 和 `orders.csv`，预览显示的总行数、合法行数和错误行数与 fixtures 说明文件一致；**预览阶段不写入业务数据**（API）。
- [ ] D2 订单 CSV 的多行商品被正确合并为一笔订单；样例中至少 3 笔多商品订单的金额和商品数正确（单测 + API）。
- [ ] D3 订单通过邮箱关联到客户；关联不上的订单在预览中单独计数（API）。
- [ ] D4 `fixtures/invalid/` 中的每个文件都会被拒绝，或在预览中逐行列出行号、字段和原因（API）。
- [ ] D5 重复导入同一个文件时，新增数为 0，客户数和订单数不变（API）。
- [ ] D6 入库过程中出错时整批回滚（单测）。
- [ ] D7 导入后，客户画像中的订单数、累计消费、末购时间、消费层级、品类偏好与 fixtures 中预先计算的期望值一致（至少 5 位客户，单测）。
- [ ] D8 退款或取消的订单不计入消费（单测）。
- [ ] D9 语言判定：带有 `lang:es` 标签、MX 国家且没有标签、US 国家的三位客户，分别被判定为 es、es、en（单测）。
- [ ] D10 包含 5 万行订单的 CSV，预览和入库各自在 60 秒内完成（人工，记录耗时）。
- [ ] D11 数据来源通过 `DataSource` 接口接入；`shopify-api` 适配器存在，只抛出“未实现”，导入流程不依赖具体实现（代码审查）。

## 3. 分群（S）

- [ ] S1 导入演示数据后，5 个场景的人数和可触达人数与 fixtures 说明文件中的期望值一致（API）。
- [ ] S2 沉睡召回使用“≥ 60 天”的口径；第 59 天和第 60 天的边界客户结果正确（单测）。
- [ ] S3 复购提醒按品类复购周期计算；修改店铺设置中的猫粮周期后，人数相应变化（API）。
- [ ] S4 没有导入弃单 CSV 时，弃购挽回显示“未导入弃单数据”（`missing_data`），而不是 0 人（API + E2E）。
- [ ] S5 活动分层推送支持按国家、语言、消费层级、品类偏好组合筛选，预览结果与直接查询数据库的结果一致（API）。
- [ ] S6 分群页面展示人数、可触达人数、语言分布和国家分布（E2E）。

## 4. 营销节点（H）

- [ ] H1 首页展示未来 45 天内的节点，包括中文名称、日期、适用市场、建议预热日期和推荐场景（E2E，使用固定的测试日期）。
- [ ] H2 测试日期为 10 月 20 日时，列表中包含黑色星期五和亡灵节；测试日期为斋月开始前 30 天时，列表中包含斋月（API）。
- [ ] H3 点击节点上的“创建活动”后，活动向导中已预填节点信息和推荐场景（E2E）。

## 5. 模型与文案（M）

- [ ] M1 **没有任何 Key 时**，生成接口返回“每种语言 × 每个渠道 × 2 个版本”，所有版本都标注为“模板生成”，并且都附中文对照（API + E2E）。
- [ ] M2 收件人中同时有英语和西班牙语客户时，分别生成英语和西班牙语文案；只有英语客户时，不生成西班牙语文案（API）。
- [ ] M3 **路由与降级**：使用伪造的大模型服务，模拟 GPT 返回 500 错误；文案改由 DeepSeek 生成，`is_fallback=true`，界面显示降级提示（API）。
- [ ] M4 GPT 和 DeepSeek 都失败时，由模板兜底，生成不会失败（API）。
- [ ] M5 中文对照默认由 DeepSeek 生成；AI 检查由 DeepSeek 执行；AI 检查失败时只缺少 AI 警告，不影响规则检查（API）。
- [ ] M6 通过环境变量把文案链设为 `doubao,...` 后，请求发往豆包的伪造地址（API）。
- [ ] M7 **个人信息隔离**：在伪造的大模型服务端记录所有请求内容；断言其中不包含演示数据中任何客户的邮箱、姓名或手机号（API）。
- [ ] M8 每次调用都写入 `llm_calls`，包括用途、供应商、模型、是否降级和耗时；**记录中不包含 Key**（API）。
- [ ] M9 单独重新生成某个版本时，只替换该版本（API）。
- [ ] M10 配置真实 Key 后，英语和西班牙语文案读起来地道，符合活动意图；中文对照准确（人工，由负责人抽查 3 个活动）。
- [ ] M11 代码中没有把 Cursor 作为模型接口的调用（代码审查 + 搜索检查）。

## 6. 文案检查与审核（R）

- [ ] R1 邮件正文缺少 `{{unsubscribe_url}}` 或 `{{company_address}}` 时，检查结果为严重问题（单测 + API）。
- [ ] R2 出现白名单以外的占位符、占位符未闭合、语言与目标语言不一致时，检查结果为严重问题（单测）。
- [ ] R3 命中违禁词表或长度超限时，检查结果为警告（单测）。
- [ ] R4 存在严重问题的版本，“通过”按钮不可用，接口返回 409 `VARIANT_HAS_BLOCKING_ISSUES`（API + E2E）。
- [ ] R5 编辑文案后重新运行检查，`edited=true`，刷新页面后状态保持不变（E2E）。
- [ ] R6 还有语言没有通过审核的版本时，发送和导出接口返回 `CAMPAIGN_NOT_READY`（API）。

## 7. 发送与导出（E）

- [ ] E1 默认（`EMAIL_SENDER` 未设置）为模拟发送：不访问网络，发送确认页和报表上明确标注“模拟发送”（API + E2E）。
- [ ] E2 发送确认页展示收件人数、排除人数及原因分布、每种语言的渲染示例（E2E）。
- [ ] E3 每封邮件中的占位符都已替换；`{{first_name}}` 为空时使用该语言的默认称呼（如 “there” 或 “hola”），不残留 `{{...}}`（API）。
- [ ] E4 配置 `EMAIL_SENDER=smtp` 并指向伪造的 SMTP 服务后，邮件被真实投递到伪造服务，并带有 `List-Unsubscribe` 头（API）。
- [ ] E5 单封邮件发送失败不影响其他邮件，失败原因被记录（单测）。
- [ ] E6 WhatsApp 导出的 CSV 包含手机号（E.164 格式）、姓名、语言、个性化文案和 wa.me 链接；手机号无效的客户被排除并计入排除原因（API）。
- [ ] E7 WhatsApp 不会自动发送：代码中没有任何 WhatsApp 发送调用（代码审查）。

## 8. 追踪与转化（T）

- [ ] T1 模拟发送后，报表显示发送、送达、打开、点击和退订数，模拟数据带有“模拟”标记；同一份数据两次运行的结果一致（API）。
- [ ] T2 点击追踪链接会记录事件并跳转到目标地址；目标不是店铺域名时拒绝跳转（API）。
- [ ] T3 发送后导入包含新订单的 CSV（fixtures 中提供“发送后订单”文件），转化客户数和转化金额与期望值一致；归因窗口外的订单不计入（API）。
- [ ] T4 使用活动折扣码的订单被标注为“折扣码归因”（API）。
- [ ] T5（P1）设置对照组后，报表分别显示发送组和对照组的转化率（API + E2E）。

## 9. 合规（C）——必须全部通过才能交付试用

- [ ] **C1 每封营销邮件都包含退订链接**：缺少 `{{unsubscribe_url}}` 的文案不能通过审核；即使绕过前端直接调用发送接口，后端也会拒绝发送（`MISSING_UNSUBSCRIBE`）（API）。
- [ ] **C2 退订链接是收件人专属的**：不同收件人的退订 token 不同，token 不可猜测（至少 128 位随机数）（API）。
- [ ] **C3 退订立即生效**：打开退订链接并确认后，该客户的 `unsubscribed_at` 被写入；之后创建的任何活动都会以 `unsubscribed` 原因排除该客户；退订页面为中性的英文或西语页面，不需要登录（API + E2E）。
- [ ] **C4 只使用已同意接收营销的客户**：`email_consent=false` 的客户永远不会出现在邮件发送名单中；`sms_consent=false` 的客户永远不会出现在 WhatsApp 导出中。演示数据中包含未同意营销的客户，断言他们在所有发送和导出结果中出现 0 次（API）。
- [ ] **C5 没有入口可以绕过同意过滤**：界面和接口都不提供“包含未同意营销的客户”的选项（代码审查 + API）。
- [ ] **C6 发送前必须填写公司地址**：店铺没有填写公司地址时，真实发送返回 `MISSING_COMPANY_ADDRESS`（API）。
- [ ] **C7 可以删除单个客户**：删除后，客户、画像、收件人和消息记录中都查不到该客户的邮箱、姓名和手机号（直接查询数据库）；活动的汇总数字仍然可以显示（API）。
- [ ] **C8 可以清空店铺数据**：输入店铺名确认后，客户、订单、弃单、活动和消息全部清空；店铺名输入错误时返回 `CONFIRMATION_MISMATCH`（API + E2E）。
- [ ] **C9 删除操作留有审计日志**：审计日志中只记录操作人、时间和数量，不包含被删除客户的个人信息（API）。
- [ ] **C10 发给大模型的数据不含个人信息**：同 M7。

## 10. 安全与配置（K）

- [ ] K1 API Key 只从环境变量读取：仓库中搜索 `sk-`、`api_key=` 等密钥特征串，结果为 0（CI 脚本）。
- [ ] K2 `.env.example` 中只有变量名、没有值；`.env` 已加入 `.gitignore`（CI 脚本）。
- [ ] K3 `/health` 只返回各供应商“已配置 / 未配置”，日志和错误信息中不出现 Key（API）。
- [ ] K4 未登录访问业务接口返回 401；访问其他店铺的资源返回 404（两个测试账号互相访问）（API）。
- [ ] K5 密码以哈希形式存储；会话 Cookie 设置了 HttpOnly 和 SameSite（API）。

## 12. 端到端演示脚本（最终验收）

在没有网络和 Key 的干净环境中执行：

```bash
pnpm install
pnpm build
pnpm --filter api run create-user -- --email demo@example.com --store "Paws Demo"
pnpm --filter api run seed-demo -- --email demo@example.com
pnpm e2e              # Playwright 全部通过
pnpm acceptance       # 输出 G/D/S/H/M/R/E/T/C/K 各条目的通过或失败报告，有失败时以非零退出码结束
```

然后人工演示（由 Agent C 录屏）：

1. 登录，首页看到即将到来的营销节点（如黑五）。
2. 进入分群页面，查看 5 个场景的人数；“沉睡召回”显示可触达人数和语言分布（英语和西班牙语）。
3. 从“黑五”节点创建活动：场景为活动分层推送，消费层级为高，渠道选择邮件和 WhatsApp，用中文写意图“黑五老客专享 8 折，主推猫砂和猫粮，强调囤货划算”。
4. 生成文案：英语和西班牙语各 2 个版本，每个版本有中文对照，标注“模板生成”。
5. 删除一个版本中的退订占位符，看到严重问题提示，“通过”按钮不可用；恢复后通过审核。
6. 发送确认页显示排除人数，其中包含“未同意营销”的客户；执行模拟发送。
7. 导出 WhatsApp CSV，确认只包含同意营销且手机号有效的客户。
8. 打开某位收件人的退订链接并退订；再创建一个活动，确认该客户被排除。
9. 导入“发送后订单”文件，报表中出现转化客户数和转化金额。
10. 删除一位客户，确认在客户列表中查不到该客户。
11. （如果负责人提供了 Key）配置 GPT 和 DeepSeek 后重复第 4 步，文案标注“由 GPT 生成”，中文对照“由 DeepSeek 生成”。

## 13. 不在第一版验收范围内

- 真实邮件的送达率和进入收件箱的比例。
- 文案的实际营销效果。
- Shopify API 接入、Shopify 应用市场上架。
- 高并发和多实例部署。
