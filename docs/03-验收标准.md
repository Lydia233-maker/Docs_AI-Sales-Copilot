# 03 验收标准

> 版本：V0.1（第一阶段）
> 状态：规划稿，等待负责人确认
> 前置文档：[01 产品定位与需求](./01-产品定位与需求.md)、[02 技术方案与目录结构](./02-技术方案与目录结构.md)

第一阶段是否完成，以本文档中的条目为准。每一条都应当能通过自动化测试、验收脚本或人工演示验证。条目编号前缀与功能编号（F1～F11）对应，括号中注明主要负责的 Agent。

## 1. 通用完成标准（每个 Agent 的每个 PR 都适用）

- [ ] G1 后端 `pytest` 全部通过；前端 `npm test` 和 `npm run build` 通过。
- [ ] G2 测试中不访问外网，不需要真实的 `LLM_API_KEY`（默认使用 `LLM_PROVIDER=mock`）。
- [ ] G3 数据库变更都有 Alembic 迁移脚本；在空库上执行 `alembic upgrade head` 能成功。
- [ ] G4 新增的接口出现在 OpenAPI 文档中，字段与 [02 第 6 节](./02-技术方案与目录结构.md#6-接口约定前后端契约) 一致；如有偏差，已同步更新文档。
- [ ] G5 只修改了本 Agent 负责的文件；修改共享文件时遵守 [04 的规则](./04-Agent分工与协作.md#4-共享文件修改规则)。
- [ ] G6 PR 描述中写明：做了什么、如何验证、有哪些已知限制。

## 2. 功能验收

### F1 店铺与数据导入（A）

- [ ] F1.1 可以创建店铺，并编辑品牌名称、品牌语气和主营品类。
- [ ] F1.2 上传 `fixtures/shopify_customers_sample.csv` 和 `shopify_orders_sample.csv` 后，预览接口返回总行数、合法行数和错误行数，**此时数据库中还没有写入业务数据**。
- [ ] F1.3 上传 `*_errors.csv` 时，预览结果逐行列出错误，包括行号、字段和原因（例如必填字段缺失、日期格式错误、金额不是数字、邮箱格式错误）。
- [ ] F1.4 确认入库后，客户数和订单数与样例文件中的合法行数一致。
- [ ] F1.5 重复导入同一个文件不会产生重复数据：按 `(store_id, external_id)` 更新已有记录，并在批次记录中统计新增数和更新数。
- [ ] F1.6 入库失败时整批回滚，不会留下部分数据。
- [ ] F1.7 空文件或完全无法识别的文件会被拒绝，并返回可读的错误信息。
- [ ] F1.8 处理 1 万行订单 CSV 时，预览和入库各自在 30 秒内完成（本地 Docker 环境）。

### F2 客户画像（A）

- [ ] F2.1 入库后自动重算 `customer_metrics`，样例数据中至少 3 位指定客户的订单数、累计消费、首购和末购时间、平均复购间隔与人工计算的结果一致（由测试断言）。
- [ ] F2.2 只有 1 笔订单的客户，`avg_repurchase_days` 为空，而不是 0。
- [ ] F2.3 没有品类数据时，`categories` 为空，界面显示“数据不足”。

### F3 预置分群（A 负责计算，C 负责界面）

- [ ] F3.1 新店铺导入数据后，自动出现 [01 第 3.2 节](./01-产品定位与需求.md#32-预置分群建议待确认) 中列出的预置分群。
- [ ] F3.2 对于样例数据，每个预置分群的人数与测试中预先计算好的期望值一致。
- [ ] F3.3 分群详情显示规则说明（中文）、人数、占比，以及聚合特征：平均客单价、热门品类前 3、主要国家前 3、同意营销的比例。
- [ ] F3.4 修改阈值配置后重新计算，人数随之变化，`rule_version` 递增。

### F4 自定义分群（A、C，P1）

- [ ] F4.1 前端条件编辑器中的字段来自 `GET /segments/fields`，不在前端写死。
- [ ] F4.2 修改条件后，预览的人数在 1 秒内更新（1 万客户规模）。
- [ ] F4.3 后端拒绝不在白名单中的字段或比较符，返回 422 错误。

### F5 营销活动创建（B 负责接口，C 负责界面）

- [ ] F5.1 创建活动时必须填写分群、营销目标（中文）、目标语言和语气，优惠信息可选。
- [ ] F5.2 创建活动的同时生成分群快照；之后重新导入数据，活动中的快照人数和特征保持不变。

### F6 AI 内容生成（B 负责接口，C 负责界面）

- [ ] F6.1 使用 Mock 供应商时，生成接口返回 `variant_count` 个版本，每个版本都包含标题、预览文本、HTML 正文、纯文本正文和中文对照。
- [ ] F6.2 配置真实供应商（`openai_compatible`）后，在人工演示中可以生成可读、符合营销目标的英文邮件。
- [ ] F6.3 **个人信息隔离**：有测试断言，发给供应商的完整请求内容中不包含样例数据中任何客户的邮箱、姓名或电话。
- [ ] F6.4 模型返回无法解析的内容时，自动重试 1 次；仍然失败时，接口返回明确的错误，`generation_runs` 中保存原始输出和错误信息，已有的内容版本不受影响。
- [ ] F6.5 单个版本重新生成时，只替换该版本，其余版本保持不变。
- [ ] F6.6 生成过程中前端显示加载状态，按钮不可重复点击；超时后显示可读的错误，并允许重试。

### F7 内容审核（B、C）

- [ ] F7.1 可以编辑标题、预览文本和正文；编辑后 `edited=true`，并重新执行合规检查。
- [ ] F7.2 可以把版本标记为通过或驳回；状态在刷新页面后保持不变。
- [ ] F7.3 存在 error 级别合规问题的版本，“通过”按钮不可用，接口也会拒绝（返回 409）。

### F8 合规检查（B）

- [ ] F8.1 正文缺少 `{{unsubscribe_link}}` 时报告 error。
- [ ] F8.2 出现白名单以外的 `{{...}}` 占位符时报告 error。
- [ ] F8.3 命中违禁词表时报告 warning；标题超过 80 个字符时报告 warning。
- [ ] F8.4 前端在对应版本旁边展示问题列表，按严重级别用颜色区分。

### F9 导出（B 负责接口，C 负责界面）

- [ ] F9.1 没有已通过的版本时，内容导出返回 409，前端给出提示。
- [ ] F9.2 名单 CSV 默认只包含 `accepts_marketing=true` 的快照成员，行数与快照中同意营销的人数一致。
- [ ] F9.3 勾选“包含未同意营销的客户”时，前端先弹出风险确认框；导出记录中 `include_non_consented=true`。
- [ ] F9.4 名单 CSV 的列至少包括 email、first_name、last_name、country，可以直接导入 Shopify Email 或 Klaviyo（以列名与对方导入模板兼容为准）。
- [ ] F9.5 每次导出都写入 `export_records`，并在活动详情中可以查看。

### F10 生成记录追溯（B）

- [ ] F10.1 任意一个内容版本都能查到对应的 `generation_runs`，包括供应商、模型、模板 key 和版本、输入特征、token 用量和耗时。
- [ ] F10.2 修改提示词模板时必须新增版本，不能覆盖旧版本；旧内容仍然指向旧版本。

### F11 简单登录（A、C，P1）

- [ ] F11.1 未登录时访问业务接口返回 401，前端跳转到登录页。
- [ ] F11.2 token 格式错误或过期时返回 401，不会导致 500 错误。

## 3. 端到端演示脚本（最终验收）

在干净的环境中执行：

```bash
cp .env.example .env
docker compose up -d --build
docker compose exec backend alembic upgrade head
docker compose exec backend python -m scripts.seed_prompts
docker compose exec backend python -m scripts.seed_demo        # 创建演示店铺并导入样例数据
docker compose exec backend python -m scripts.run_acceptance   # 自动化验收，全部通过才算成功
```

然后打开前端，人工完成以下流程，每一步都应当符合预期：

1. 登录（如果实现了 F11），进入演示店铺。
2. 在“数据导入”页面再次上传样例订单 CSV：预览显示全部为更新、没有新增，确认后客户总数不变。
3. 在“客户分群”页面查看“新客首单未复购”：人数和特征与验收脚本的输出一致。
4. 用该分群创建营销活动，目标填写“推新品，配合 9 折券，促进第二单”，语言选英语，语气选友好。
5. 生成 3 个版本；切换中文对照；删除其中一个版本中的退订占位符，看到 error 提示且无法标记为通过；恢复占位符后标记为通过。
6. 导出名单 CSV 和内容 HTML；打开 CSV，确认只包含同意营销的客户；在导出记录中看到这两次导出。
7. 切换到真实大模型配置（如果已提供 Key），重复第 5 步，生成内容可读且符合目标。

`run_acceptance.py` 至少覆盖第 2～6 步对应的接口断言，并输出每一步“通过/失败”的汇总，失败时以非零退出码结束。

## 4. 不在第一阶段验收范围内

- 真实的邮件发送和送达率。
- AI 文案的营销效果（打开率、转化率）。
- 多租户隔离、性能压测、高可用部署。
