# 画像定向营销需求说明

> 状态：根据 2026-10-11 的讨论整理。已经说定的写在下面；没说清的放在「待确认」，不计入这一版功能。
> 这一版要证明的事：独立站商家不用逐个写备注，系统根据客户画像生成定向邮件，销售只做审核。
> 对照：`docs/01` 到 `docs/04` 仍是完整试用版目标。本文没写进去的，不自动算进这一版。
> 产品名仍是 **AI定向营销助手**。版本号到发布时再定。

## 1. 目标用户

中国跨境电商里、做独立站的中小商家：店主和运营。

他们用中文工作。收件人是这些商家自己的海外个人顾客。文案语言是英语或西班牙语，并给出中文对照。

## 2. 最核心的使用场景

一家店有大约两千到三千个客户。销售不会给每个人手写备注，也不会自己写每封信。

运营用中文写清这场推广要说什么，例如「黑五老客 8 折，主推猫砂，强调囤货」。系统用已经算好的画像挑出这场该联系的人，由 AI 为他们写成英语或西班牙语邮件。购买记录能说明的事直接写进信。聊过天才有的事实，先抽出来给销售确认，确认之后才能写进信。

销售打开审核页，看中文对照和这封信用了哪几条事实。事实和优惠都对，就通过。未同意接收营销的客户不生成、不发送。

演示时仍要能用现有的 Paws Demo 数据把这条链路走完。Anna Cole 这种客户：英语、美国、主买猫砂、已经 90 多天没买。若确认过「无尘猫砂 / 布偶猫」这类事实，信里要使用它。只有一单、没有额外事实的客户，和同一群人共用一封信，姓名和上次商品仍是他自己的。

## 3. 画像怎么用

一个维度要留下，是因为它会改变「这场找谁」，或者改变「信里的某一句」。

| 层 | 已经确定要使用的内容 | 在这场里做什么 |
| --- | --- | --- |
| 能不能发 | 邮件营销同意；是否已退订 | 决定生成和发送 |
| 用什么语言 | 语言；国家 | 决定英语还是西班牙语。国家用于区分市场 |
| 这场找谁 | 场景、主要品类、距上次购买、购买次数、消费层级 | 决定进不进这场，以及没有额外事实的人能否共用一封信 |
| 写给这个人 | 最近购买的具体商品；已确认的偏好；已确认的、需要小心的事 | 决定这封信和别人有什么不同 |

购买历史本身就是画像，不抄进备注。备注和聊天只用来补充订单里没有的两类事实：

- **偏好**，例如无尘猫砂、布偶猫。
- **需要小心的事**，例如物流延迟已经补偿。

姓名、邮箱、电话不是画像。它们不发给模型，只在审核通过后的渲染里通过占位符填入。

「认不认识」不另建字段：买过至少两次，或者已有确认过的偏好、需要小心的事，就单独写一封；否则与同一群人共用一封，再填入姓名和上次商品。

时机不另建字段。复购和沉睡用品类与距上次购买的天数计算。

有折扣码时，优惠写法沿用已经确定的做法：写 20% off，不从中文意图里解析折扣幅度。

## 4. 核心功能点

1. **导入并算出画像。** 页面上传客户 CSV 和订单 CSV。自动得到语言、国家、主要品类、最近购买的商品、购买次数、距上次购买的天数、消费层级、是否同意邮件营销。Shopify 客户 CSV 里已有的 Note 列导入为备注。
2. **按画像挑选客户。** 场景包括沉睡召回和复购提醒。沉睡召回沿用已确认口径：最后一次购买距今不少于 60 天。可以用语言、品类、消费层级缩小人群。生成前显示人数，以及多少人单独写、多少人共用一封。
3. **AI 按画像写信。** 销售只填写这场的中文意图和折扣码，不撰写每封信。默认模型是 DeepSeek；没有 Key 或调用失败时用本地模板，保证能离线演示。模型同时给出外语正文和中文对照。外语正文使用该客户的商品、天数和品类；中文意图写成优惠说明，不把中文原句贴进外语正文。
4. **不同画像，不同的信。** 商品、天数或品类不同的客户，正文要能看出来。没有额外事实的人可以共用一封，渲染后的姓名和上次商品仍是各人自己的。
5. **聊天事实先确认再用。** 导入一份客服或邮件导出。系统从中抽出「偏好」和「需要小心的事」，并保留原话。销售确认后，这些事实才进入画像，AI 才可以写进信。未确认的不使用。
6. **销售审核后模拟发送。** 每封信标出用了哪些事实。正文必须包含退订链接和公司地址占位符，否则不能通过。模拟发送只处理已通过、且同意营销的草稿。

复购周期的天数沿用 `docs/01-产品定位与需求.md` 里已经确认的口径：猫砂 21 天，猫粮和狗粮 30 天，零食 14 天，允许上下 7 天。本轮讨论没有改过这些数字。

发给模型的备注和聊天摘录，沿用现有规则：邮箱和电话先遮盖。

## 5. 这一版先不做

- 营销节点首页
- 转化报表
- WhatsApp 的复制、wa.me 和导出
- 真实邮箱发送（SMTP）
- 国内阿里云部署
- 批发客户的文案
- 商品 CSV，以及由此重建品类
- 售前、售中、售后聊天的自动同步
- 销售为两千到三千个客户逐个手写备注

以下内容在 `docs/01` 或 `docs/TODO.md` 里出现过，本轮说定的功能清单里没有。在得到明确答复前，不放进这一版：

- 首单转二单、弃购挽回
- 手动勾选或去掉个别客户
- 销售在页面上修改客户语言
- 单份重新生成
- 生成前显示调用次数和费用
- 退订页面（打开后写入退订状态）
- 页面上修改公司地址
- 从商品标题自动提议偏好标签

## 6. 待确认

下面这些会影响功能范围。文档里先不替它们选一个做法。

1. 审核时，销售只能通过，还是也可以改正文、驳回一封？讨论里出现过「只审核」，也出现过「不对就改一句」。
2. 聊天导出从哪个工具来，文件里用什么字段对应到 Shopify 客户？这一版要接哪一种导出？
3. 销售手写一条备注或偏好标签，这一版是否保留？批量手填已经明确不做。
4. 「两千到三千个客户」是这一版必须完成导入和生成的规模，还是只用来说明不能靠手写备注？
5. 客户类型（零售 / 批发）这一版要不要显示？批发文案已经明确不做。Shopify 客户 CSV 里通常没有这一列。
6. 模型失败后的顺序，是否仍按已有决定走 DeepSeek → OpenAI → 本地模板？本轮清单里只明确了 DeepSeek 和模板。
