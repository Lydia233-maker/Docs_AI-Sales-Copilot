## 1. 今晚初稿要做成什么样

一个人、一台电脑、**没有 API Key、没有网络**，两小时内能走完：

**登录 → 看到演示客户 → 挑一批人 → 用中文写推广意图 → 系统给每人生成一份不同的文案（英语或西班牙语 + 中文对照）→ 审核 → 模拟发送**

- 编号就是执行顺序。初稿由**主 Agent 一个人按顺序做**，不拆 A/B/C，也不开三个 worktree。
- 除特别说明外，都在离线、没有 Key 的情况下验证。
- 演示里的“今天”固定为 `2026-11-01`。

启动方式（任务 1 完成后）：

```bash
pnpm install
pnpm --filter api run seed   # 创建演示账号并灌入数据
pnpm dev                     # 前端 5173，后端 3000
```

演示账号：`demo@example.com` / `demo1234`。

## 4. 任务详情

### 任务 1：仓库骨架和前后端空壳

- **依赖**：无
- **做什么**：pnpm workspace（`apps/web`、`apps/api`、`packages/shared`）；根目录脚本 `dev` / `build` / `test`；`.gitignore`、`.env.example`（只有变量名）；Vite + React 空页面；Fastify 只提供 `/health`。
- **怎么算做完**：
  1. `pnpm install` 成功。
  2. `pnpm --filter api dev` 后，`curl http://localhost:3000/health` 返回含 `"status":"ok"`。
  3. `pnpm --filter web dev` 后，打开 `http://localhost:5173`，标题是“AI 定向营销助手”。

### 任务 2：初稿用到的共享类型

- **依赖**：1
- **做什么**：只定义初稿会用到的枚举和请求/响应类型：登录、客户、备注、挑选、推广、草稿、发送。占位符白名单：`{{first_name}}`、`{{last_product}}`、`{{discount_code}}`、`{{unsubscribe_url}}`、`{{company_address}}`。发给模型的客户简报类型**不能出现**姓名、邮箱、手机号字段。
- **怎么算做完**：
  1. `pnpm --filter shared test` 通过。
  2. 用一份带 `email` 字段的对象去校验“客户简报”，校验失败。
  3. `isAllowedPlaceholder('unsubscribe_url')` 为真，`isAllowedPlaceholder('frist_name')` 为假。

### 任务 3：宠物用品演示数据

- **依赖**：1
- **做什么**：`fixtures/demo-pet/` 放 Shopify 格式的客户 CSV、订单 CSV，以及 `notes.json`。大约 40 位客户、约 80 笔订单。必须覆盖：英语和西班牙语客户、有备注的熟客、只下过一单的新客、未同意营销的客户、一笔多商品订单。写一份 `README.md`，写明以 `2026-11-01` 为今天时的期望人数。
- **怎么算做完**：
  1. 用 Excel 打开两个 CSV，表头能对上 Shopify 导出（`Customer ID`、`Email`、`Accepts Email Marketing`、`Name`、`Lineitem name` 等）。
  2. 所有邮箱都以 `@example.com` 结尾。
  3. README 里写明：总客户数、未同意营销人数、沉睡客户（末购 ≥ 60 天）人数、有备注的人数。

### 任务 4：数据库、登录、店铺

- **依赖**：2
- **做什么**：SQLite 单文件；账号、店铺、客户、订单、备注、推广、收件人、草稿、消息这些表；`seed` 脚本创建 `demo@example.com` / `demo1234` 和店铺 “Paws Demo”；登录后发 Cookie 会话；`GET /api/v1/auth/me`、`GET /api/v1/store`。
- **怎么算做完**：
  1. `pnpm --filter api run seed` 后，用错误密码登录返回 401；用正确密码登录返回 200，响应头有 `HttpOnly` Cookie。
  2. 带 Cookie 调 `/api/v1/auth/me`，店铺名是 “Paws Demo”。
  3. 不带 Cookie 调业务接口返回 401。
  4. 打开数据库文件，密码列是哈希，看不到 `demo1234`。

### 任务 5：导入演示 CSV，算出客户档案

- **依赖**：3、4
- **做什么**：读入任务 3 的 CSV（列名忽略大小写和空格）；订单按订单号合并多行商品，用邮箱关联客户；算出订单数、累计消费、末购时间、消费层级、主要品类、语言。`seed` 自动导入。
- **怎么算做完**：
  1. seed 之后，`GET /api/v1/customers` 的 `total` 等于 README 里的总客户数。
  2. README 点名的一位多商品订单客户，详情里的订单数和金额对得上。
  3. 语言：`lang:es` 或国家 MX/ES 为西班牙语，其余默认英语。

### 任务 6：客户列表、详情、备注

- **依赖**：5
- **做什么**：客户列表支持搜索和按语言筛选；详情显示档案、订单、备注；可以添加备注和偏好标签。
- **怎么算做完**：
  1. `GET /api/v1/customers?language=es` 的人数等于 README。
  2. 给一位客户加备注“喜欢无尘猫砂”，再打开详情能看到这条备注。
  3. seed 进来的 `notes.json` 已经挂在对应客户上。

### 任务 7：挑选客户，创建推广

- **依赖**：6
- **做什么**：两个筛选：沉睡召回（末购 ≥ 60 天）、全部客户；再加语言、是否有备注。预览返回人数、可触达人数（已同意营销）、语言分布。创建推广时冻结名单，未同意营销的人标成排除，不为他们生成文案。单批最多 40 人（初稿按演示规模）。
- **怎么算做完**（`APP_NOW=2026-11-01`）：
  1. 预览“沉睡召回”，人数等于 README。
  2. 用这批人创建推广，返回的可触达人数 = 总人数 − 未同意营销人数。
  3. 未同意营销的人在收件人里，排除原因是 `no_email_consent`。

### 任务 8：按客户生成模板文案

- **依赖**：7
- **做什么**：可触达的每位客户生成一份草稿。信息够的（订单 ≥ 2，或有备注/标签）按这个人的商品和备注填模板；信息少的用更通用的模板，但仍插入姓名和上次买的商品。每人的邮件是英语或西班牙语，并带中文对照。正文必须带 `{{unsubscribe_url}}` 和 `{{company_address}}`。没有 Key，只用模板。
- **怎么算做完**：
  1. 调用生成接口后，草稿份数 = 可触达人数。
  2. 打开两位购买记录不同的客户，草稿正文里出现的商品名不一样。
  3. 给客户写过“喜欢无尘猫砂”，这份草稿的中文对照或定制说明里能看到“无尘猫砂”。
  4. 西班牙语客户的邮件是西班牙语，英语客户的是英语，每份都有中文对照。

### 任务 9：审核、一键通过、模拟发送

- **依赖**：8
- **做什么**：草稿列表；可以改正文；缺退订占位符时不能通过；其余可以一键通过；模拟发送把邮件写入数据库，不访问网络；提供“复制”接口，返回填入姓名后的最终文本。
- **怎么算做完**：
  1. 删掉一份草稿里的 `{{unsubscribe_url}}`，点通过，接口拒绝。
  2. 一键通过后，可触达且没有问题的草稿都变成已通过。
  3. 模拟发送后，消息表的行数 = 已通过的份数；每封有不同的退订 token。
  4. 复制接口返回的文本里已经有客户名字，看不到 `{{`。

### 任务 10：前端框架和登录页

- **依赖**：2
- **做什么**：中文界面；登录页；登录后左侧导航：客户、挑选客户、推广；请求打到后端（开发时 Vite 代理 `/api`）。
- **怎么算做完**：
  1. 打开 `http://localhost:5173`，先看到中文登录页。
  2. 错误密码提示“邮箱或密码错误”。
  3. 正确密码进入后，左侧能看到“客户”“挑选客户”“推广”。

### 任务 11：前端客户列表和详情

- **依赖**：10
- **做什么**：客户列表（搜索、按语言筛选）；点进去看档案、订单、备注；可以加备注。
- **怎么算做完**：
  1. 打开客户页，能看到约 40 位客户，列表里有国家和语言。
  2. 筛“西班牙语”，列表只剩西语客户。
  3. 点开一位有备注的熟客，能看到购买过的品类和备注。
  4. 现场加一条备注，刷新后还在。

### 任务 12：前端挑选客户和生成

- **依赖**：11
- **做什么**：选“沉睡召回”或“全部”，看预览人数；填中文意图和折扣码；点生成；看到“正在为 N 人生成”。
- **怎么算做完**：
  1. 选沉睡召回，页面上的人数和可触达人数对得上。
  2. 意图填“黑五老客专享 8 折，主推猫砂和猫粮”，能点“开始生成”。
  3. 生成结束后自动进入审核页，人数和可触达人数一致。

### 任务 13：前端审核和模拟发送

- **依赖**：12
- **做什么**：审核列表（每位客户一行，能看到语言和定制说明）；点开并排看外语和中文；能改、能通过；一键通过；发送确认页标明“模拟发送”；有复制按钮。
- **怎么算做完**：
  1. 列表里每位客户一行，两位客户的文案摘要不一样。
  2. 点开西语客户，左边是西班牙语，右边是中文。
  3. 删掉退订占位符后，“通过”按钮不可用。
  4. 一键通过后点发送，看到“模拟发送”标签，成功后提示已发送。
  5. 点复制，粘贴出来是填好名字的完整邮件。

### 任务 14：前后端串起来走通

- **依赖**：9、13
- **做什么**：用真实后端（不要假数据）把任务 10～13 的页面全部接上；修掉对不上的字段。
- **怎么算做完**：
  1. 只开 `pnpm dev` 和已经 seed 过的数据库，不要任何 Key。
  2. 你自己点一遍：登录 → 客户 → 加备注 → 挑选沉睡客户 → 写意图 → 生成 → 审核 → 模拟发送 → 复制。中途不能出现红字报错。
  3. 浏览器控制台没有红色错误。

### 任务 15：合规底线

- **依赖**：14
- **做什么**：发送、复制都走同一个“能不能发给这个人”的判断；未同意营销的人没有草稿，也不能复制；缺退订占位符不能通过、不能发送。
- **怎么算做完**：
  1. 未同意营销的客户，在这次推广里没有草稿。
  2. 就算直接调发送接口，也不会给他们发信。
  3. 缺 `{{unsubscribe_url}}` 的草稿，通过和发送都被拒绝。

### 任务 16：README 启动说明

- **依赖**：15
- **做什么**：根目录 README 写清：怎么安装、怎么 seed、怎么启动、演示账号、两小时演示该点哪些页面。
- **怎么算做完**：
  1. 按 README 从零执行三步，能打开登录页。
  2. 按 README 的演示路径，你能独立走完任务 14 的那条路径。
