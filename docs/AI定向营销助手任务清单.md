## 1. 怎么看这份清单

- **编号就是建议的执行顺序。** 每个任务都足够小，一次对话、一次提交（一个 PR）就能做完。
- **负责人**：`主` = 主 Agent；`A` = 前端（只改 `apps/web`）；`B` = 后端（只改 `apps/api`）；`C` = 测试与验收（只改 `tests/e2e`）。
- **依赖**：列出的任务必须先做完，本任务才能开始。C 的测试任务可以提前开始写，但要等列出的依赖完成后才能跑通，跑通了才算做完。
- **怎么算做完**：每一条都可以由你亲自操作验证。除特别说明外，都在**没有任何 API Key、没有网络**的情况下验证。
- 不同负责人的任务可以并行。例如任务 10 完成后，任务 11（B）、38（A）、50（C）可以同时开始。

### 验证前的通用准备

第 12 个任务完成后，后端接口可以这样调用（在仓库根目录执行）：

```bash
pnpm --filter api dev                                    # 启动后端，地址 http://localhost:3000
curl -c cookie.txt -H 'Content-Type: application/json' \
  -d '{"email":"demo@example.com","password":"demo1234"}' \
  http://localhost:3000/api/v1/auth/login                # 登录，并把会话保存到 cookie.txt
curl -b cookie.txt http://localhost:3000/api/v1/auth/me  # 之后的请求都带上 -b cookie.txt
```

演示数据中“今天”的日期固定为 `2026-11-01`。验证分群、节点、转化时，先在 `.env` 中设置 `APP_NOW=2026-11-01`。各项期望数字以 `fixtures/demo-pet/README.md` 为准（任务 8 产出）。
