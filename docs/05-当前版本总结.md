# 05 当前版本总结

> 这是更早的 V0.1 说明。当前代码以 [画像定向当前版本总结V1.md](./V1/画像定向当前版本总结V1.md) 为准。下面关于「不能上传 CSV」「不能改语言」「不能改公司地址」「网页不引用共享包」已经和代码不符。

> 版本：V0.1（可离线演示）
> 对照的是当时的代码，不是 `docs/01` 里的完整试用版。
> 完整需求见 [01-产品定位与需求.md](./01-产品定位与需求.md)。初稿任务见 [AI定向营销助手任务清单.md](./AI定向营销助手任务清单.md)。

这个版本卖给跨境卖家的店主、销售、运营。他们用中文写清这次想说什么，系统按每位顾客的购买记录和备注，生成一封英语或西班牙语邮件，并给出中文对照。审核后用模拟方式“发出”。不需要 API Key，断网也能演示。

演示店名 **Paws Demo**，账号 `demo@example.com` / `demo1234`。演示数据是宠物用品。程序里的“今天”默认是 `2026-11-01`。

## 1. 这个版本做了哪些功能

- 登录、退出。会话放在 Cookie 里。
- 客户列表（40 人），可按英语 / 西班牙语筛选。
- 客户档案：国家、语言、订单数、消费金额、消费层级、主要品类、距今天数、是否同意营销、备注、偏好标签。金额按美元显示，库存的是“分”。
- 销售可以追加备注、添加偏好标签。备注里的邮箱和电话会提示，并在写入文案前遮盖。
- 挑选客户：沉睡召回（距上次购买至少 60 天），或全部客户。生成前显示总人数、可触达人数、因未同意营销而排除的人数，以及逐个定制 / 小群方式的人数。
- 用中文填写推广意图和折扣码，然后为每位可触达客户生成一封邮件。
- 每封邮件有外语标题、外语正文、中文对照和定制要点。语言按客户标签或国家决定。
- 可以改正文、单份通过、一键通过。缺少 `{{unsubscribe_url}}` 或 `{{company_address}}` 时不能通过，也不能发送。
- 模拟发送。复制时在页面上看到已经填好姓名、商品、折扣码、退订链接和公司地址的正文。
- 未同意营销的客户仍出现在客户列表里，但不会生成文案，也不会进入发送。

新鲜种子数据下的人数：客户 40，西班牙语 16，沉睡 32，其中可触达 27（英语 14、西班牙语 13），排除 5。

## 2. 已知限制和还没做完的部分

界面能走通的是「登录 → 看客户 → 沉睡召回 → 生成 → 审核 → 模拟发送 → 复制」。下面这些在完整需求里有，当前版本没有，或只做了一部分。

**数据**

- 不能在页面上上传 Shopify CSV。数据来自 `pnpm seed` 灌入的 `fixtures/demo-pet/`。
- 客户 CSV 里的短信营销同意、电话没有入库。客户类型（零售 / 批发）没有这个字段。
- 销售不能在页面上修改客户语言。

**挑选和生成**

- 场景只有沉睡召回和全部。没有复购提醒、首单转二单、弃购挽回。
- 不能按国家、消费层级、品类、标签筛选，也不能手动勾选。没有单批 200 人的上限。
- 「小群方式」只是人数统计。生成时每个人仍然各写一封，用的是同一套模板。
- 文案来自本地模板 `apps/api/src/templates.ts`。默认模型已定为 DeepSeek，但 V0.1 还不会发起模型请求。环境变量里即使填了 Key，也只在 `/health` 里显示“有 Key”。
- 顾客收到的英/西语正文会写上次买的商品和距今天数。备注原文、偏好标签原文写在中文对照和定制要点里，不写进外语正文。
- 中文推广意图会原样出现在外语正文中。
- 只要填了折扣码，模板就写成 20% off。这是 V0.1 确认的做法，不从意图里解析折扣幅度。
- 标签或备注是在点「开始生成」之后才加的，已经生成的文案不会自动改写。要看到新标签，需要再生成一次。
- 没有预览文本、重新生成、进度条。某一位客户生成失败时，整批会失败。

**发送、合规、之后的效果**

- 发送永远是模拟。`EMAIL_SENDER` 和 SMTP 变量还没有接到发送逻辑上。
- 退订链接会写进邮件，打开后没有退订页面，也不会把这个人记成已退订。
- 公司地址是种子数据里的 `123 Demo St, Austin, TX 78701`，页面上不能改。
- 没有 WhatsApp 文案、wa.me 或导出。
- 没有营销节点首页，没有转化报表，不能删除客户或清空店铺。

## 3. 怎么运行

在仓库根目录：

```bash
pnpm install
pnpm seed
pnpm dev
```

- 前端：http://localhost:5173
- 后端：http://localhost:3000
- 打开网址会进入登录页。邮箱 `demo@example.com`，密码 `demo1234`。

`pnpm seed` 会清空这家演示店已有的客户、订单、备注、标签和推广，再灌入 40 人。人数和上面不一致时，先停掉服务，再执行一次 `pnpm seed`。

`fixtures/demo-pet/` 里的 CSV 已经提交。一般不用再跑 `node fixtures/demo-pet/generate.mjs`。

如果 `pnpm seed` 报错说 better-sqlite3 找不到 `.node` 文件，在仓库根目录执行：

```bash
pnpm rebuild better-sqlite3
```

然后再 `pnpm seed`、`pnpm dev`。

页面上的逐步点击说明在根目录 `README.md` 的「端到端操作清单」。

把“今天”改成别的日期时，要在启动后端的那个进程里设置环境变量，例如：

```bash
APP_NOW=2026-11-01 pnpm --filter api dev
```

只把 `APP_NOW` 写进 `.env` 不会生效。当前程序不会读取 `.env` 文件。

## 4. 以后接着改时要注意的地方

规划文档 `docs/02-技术方案与目录结构.md` 和 `docs/AI定向营销助手技术方案.md` 写的是完整试用版的目标结构（适配器、迁移、验收命令 `pnpm acceptance`）。那些文件和命令大多还没有。改这份初稿时，以现在的目录为准：

| 现在在哪 | 做什么 |
| --- | --- |
| `apps/web` | 页面。请求封装和前端类型在 `src/api.ts` |
| `apps/api/src/app.ts` | 接口 |
| `apps/api/src/templates.ts` | 文案模板和退订/地址检查 |
| `apps/api/src/db.ts` | 建表。没有迁移工具 |
| `apps/api/src/seed.ts` | 灌入演示 CSV |
| `packages/shared` | 请求校验、占位符白名单、发给生成逻辑的客户简报 |
| `fixtures/demo-pet` | 演示客户和订单 |

### 临时方案，以后要换掉

1. **文案生成。** 现在直接调用 `generateTemplate`。以后改成每个客户一次模型调用，同时返回外语和中文；失败顺序是 DeepSeek → OpenAI → 现有模板。Key 只从环境变量读，不要写进代码、文档或日志。豆包留作可配置项。不要把 Cursor 当成模型接口。
2. **发送。** `POST /api/v1/outreach/:id/send` 把状态直接写成已送达，返回 `sender: 'mock'`。接 SMTP 时保留模拟为默认，演示邮箱继续用 `@example.com`。
3. **小群方式。** `generationMode` 已经能区分「逐个定制」和「小群」，但生成循环没有按小群共用一封信。接模型前要先补上分组，否则调用次数会对不上。
4. **今天的日期。** `appToday()` 默认 `2026-11-01`。这是为了让沉睡人数固定。正式环境应使用真实日期，并明确店铺时区。边界差一天，沉睡人数就会变。
5. **公司地址和退订。** 地址是种子里的演示地址。退订 URL 指向 `http://localhost:3000/u/<token>`，路由还没做。登录校验已经放行 `/u/`，补页面时不要再要求登录。
6. **数据库结构。** 表是 `CREATE TABLE IF NOT EXISTS`。给已有表加列时，旧的 `apps/api/data/app.db` 不会自动更新。改完表要重新 `pnpm seed`，或另写迁移。这个库文件已被 git 忽略。

### 改代码时容易踩的地方

- **订单 CSV 一行是一个商品，不是一笔订单。** `seed.ts` 按订单 `Name` 合并。若改成一行算一单，订单数和金额会翻倍。客户和订单用小写邮箱关联。
- **金额用整数“分”。** 显示时再除以 100。不要改成浮点美元。
- **发给生成逻辑的简报不能带姓名、邮箱、手机号。** 类型是 `packages/shared` 里的 `CustomerBriefSchema`，多出来的字段会被拒绝。姓名只通过 `{{first_name}}` 在复制和发送时填回。
- **新的发送、复制、导出都要经过 `isEmailEligible`。** 未同意营销的客户不能因为新写了一个查询就被发到。
- **查询要带 `store_id`。** 现在只有一家演示店，漏掉以后会串数据。
- **接口用驼峰，数据库列用蛇形。** 例如库里是 `intent_zh`，接口返回 `intentZh`。推广列表、订单、已发送记录已经在 `app.ts` 里转换。`/api/v1/auth/me` 和 `/api/v1/store` 仍直接返回 `company_address`。新增接口时在返回前转换，并同时改 `apps/web/src/api.ts`。网页工程没有依赖 `packages/shared`，只改一边，页面会拿到空字段。
- **没有正文的 POST 不要加 `Content-Type: application/json`。** Fastify 会把空正文当成 400。`api.ts` 只在有正文时加这个头。生成、一键通过、模拟发送都走这条规则。
- **占位符白名单在 `packages/shared`。** 新增占位符时要同时改白名单、`renderCopy` 和 `checkDraft`。白名单以外的占位符不能通过审核。
- **SQLite 只适合一个后端进程。** 数据库文件路径相对于进程当前目录，`pnpm --filter api` 的目录是 `apps/api`，所以库在 `apps/api/data/app.db`。从别的目录启动会另开一个空库。
- **`pnpm seed` 会删掉演示店的全部业务数据。** 手头正在看的推广、手打的备注和标签都会没。
